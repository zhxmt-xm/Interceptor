# 组件规范：Settings 与 Agent

> 返回 [设计系统索引](README.md)

- **默认捕获与 HTTPS**：应用进入 Capture 后自动启动 loopback listener 并尝试接管系统代理，不弹启动向导。默认不生成、不安装 CA，也不解密 HTTPS；CONNECT 以 `TLS / encrypted` tunnel 摘要展示，只保存 host/port/open-close/duration 等连接元数据。选中 tunnel 时 Inspector 只显示 TLS tunnel 页和明确的隐私说明；`Decrypt HTTPS` 打开三步弹层（生成本地 CA → 显式系统信任 → 开启 MITM）。信任成功后第三步显示黄色 `Ready` 提示，但不得自动开启 MITM，必须等待用户点击 `Start decrypting`；未完成前 HTTPS 始终原样透传。禁用或未完成步骤使用统一 disabled 视觉，不以 hover 暗示可操作。
- **Settings / AppContainer access 与 TLS passthrough**：两者必须是 Settings 左侧导航中的独立页面，不能合并成一个 Windows App bypass 开关。
  - **AppContainer access**：顶部固定显示 UAC 与权限范围警告；说明 exemption 允许目标容器访问本机全部 loopback 服务、退出后继续保留。内容区提供按 display name / package family / SID 搜索、刷新、结果计数与逐项 Switch；SID 是稳定主键，AAD Broker 只显示 `Windows SSO · Recommended`，初始仍为 Off，不默认开启任何容器。切换前弹确认框，再进入 Windows 管理员批准；新安装或首次运行的容器由 Refresh 重新枚举。
  - **TLS passthrough**：host pattern 使用 mono 输入、明确校验、列表与删除按钮，`*.wvd.microsoft.com` 可标记为 Windows 365 推荐项。名单保存后由 listener 在每条新连接上重新求值，不重启 listener、不打断其他连接；已失败连接仍需客户端重试。空列表明确表示所有 host 都会尝试 HTTPS interception。passthrough 流量仍经过 Interceptor 与现有上游，只保留 CONNECT / tunnel metadata。
  - **TLS compatibility 提示**：`cert-rejected` 可给高置信建议；`reset` / `closed` 只能写“可能不兼容 MITM”，不得断言 pinning。提示必须显示 host、观测信号和“失败连接需重试”，只有用户点击保存后才加入名单，永不自动降级。
- **Settings / Agent Tool capabilities**：位于`Configured models`下方，使用同宽的紧凑表格而非卡片网格。Header左侧只显示标题与一句作用说明，右侧是`226px`搜索框；列固定为`Capability / Agent / MCP`，正文按Capture、Rules、Composer、Breakpoints、Diagnostics五个feature分组。每行显示人类可读名称、`query/change`徽标、mono Tool name与单行说明，右侧两个Ant Switch独立控制入口，默认全开；关闭态只改变目标Switch，不整行变灰。列表只渲染共享registry中已实现Tool，完整目录过长时由Settings内容面滚动，搜索不重置开关。
- **Settings / MCP Server**：位于`Configured models`与`Tool capabilities`之间，宽度与两者一致。Header使用30px Server图标、标题/单行说明、带6px圆点的`Off / Running / Port unavailable`状态和Ant Switch；默认Off且无listener。首次启用后显示mono loopback endpoint与复制图标，Client区才允许Add。Client每行使用30px Host图标、名称/连接状态、常驻`Ask / Auto` Segmented以及Copy config、Regenerate credential、Revoke三个图标命令；Token明文永不出现在Renderer。Client不区分VS Code、Claude或Cursor等Host品牌，复制动作始终产出同一份标准Streamable HTTP配置。停用/启用只改变listener，不移除Client或轮换凭据；Regenerate和Revoke必须分别经过显式确认。端口冲突以内联红色状态带展示，并只提供明确的`Change endpoint`命令，不静默换端口。首期只支持原生Host的loopback Streamable HTTP，不显示stdio或远程配置入口。
  - Header与Endpoint之间增加常驻只读协议说明，列明`2026-07-28`及兼容的`2025-11-25`、`2025-06-18`，说明自动适配Client，不增加版本开关。使用`--text-2`、`10.5px/16px`、上下8px/左右14px内边距和既有底边框；窄窗口自然换行，Off/Running/Port unavailable均保留。
- **Acceptance Playground**：独立Web App，不使用Desktop Sidebar/Header/Statusbar。唯一`1600×900`设计基线为`220px`一级导航 + 页面专属`58px`顶部栏；一级导航固定`Capture Lab`第一且默认、`MCP`第二，MCP endpoint、协议与credential只在MCP页显示。页面内容为`260px目录 / minmax(440px,1fr)操作 / 1px splitter / 560px详情`，详情可在动态`360px..(总宽 - 一级导航 - 目录 - 操作区 - 轨道)`范围拖拽，窄屏保留全部栏并允许整体横向滚动。Capture目录覆盖HTTP、Bodies、Encoding、WebSocket、gRPC与TLS当前能力，Request Draft可编辑和Reset且不持久化；MCP目录只消费在线`tools/list`。操作区显示Raw JSON、schema、annotations、人工Setup/Observe与Call/Abort；Response Detail显示脱敏交换、SDK/Origin结果和Pass/Fail/Blocked。Bearer只显示SHA-256摘要，任何可下载证据都不含明文。Playground明暗截图位于`shots/*/playground/`，不作为Desktop visual parity目标。
- **MCP Client与审批Dialog**：Add Client Dialog只收用户可辨识名称，创建后默认Ask，不提供Host类型选择。Regenerate Dialog必须说明当前MCP配置会立即失效，并明确写出app重启不会自动轮换；Revoke Dialog说明目标Client的在途调用会关闭。外部MCP change Tool的问询是App级Modal，不属于Agent Chat Transcript；显示可信Client label、不可信reported name只作辅助、Tool name、完整参数和真实Effect，并提供`Deny Tool call / Allow Tool call`。主窗口隐藏或最小化时由Main恢复并聚焦该Modal；query与Auto调用不显示它。
- **Agent Tool执行模式与问询**：每个Chat在Composer指标行提供`Ask / Auto` Segmented，默认Ask；模式属于Chat，新Chat不继承上一Chat的模式或Tool结果。它与Model Select、Context Usage共用固定高度并允许模型名ellipsis；Context圆环固定为`18px`，悬停或键盘聚焦整个Context入口时在其上方显示Session Usage详情。Agent栏收缩到`220px`时指标改为两行grid，所有控件仍在栏内。query Tool不触发问询；Ask模式下change Tool在Transcript原调用位置显示内联问询卡，不使用全局Modal。卡片必须显示Tool name、`change`类型、参数与真实影响，底部提供`Deny Tool`和实心主按钮`Allow Tool`；pending问询随当前Chat跨Workspace保持，切换到Auto只影响后续调用，不得隐藏已经pending的裁决。裁决后原位收敛为带`role=status`的Allowed/Denied结果行并接收焦点；Allowed在Tool名后显示与query Tool共用的脱敏typed结果摘要，Denied只显示裁决，摘要可单行ellipsis但结果行不得横向溢出。Auto下的新调用不显示问询卡，但仍沿用正式产品Dialog、UAC和系统权限。
- **Agent Diagnostics结果**：沿用现有Tool activity列表，依次显示`discover_tools`与`diagnostics_query`；query不出现审批。结果行仅显示记录数、分页状态和丢弃数，不展开attributes；四条记录示例与明暗`panel-diagnostics-tools`截图保持一致，不新增卡片或布局变体。
- **Agent Provider类型菜单**：每个option固定`32px`高，左右内边距`8px`，Provider图标`14px`，图文间距`8px`，文字`12px / 500`；菜单按最长option自然宽度收敛，最长文字右侧保持`8px`，不使用Ant默认的大号菜单密度。
- **Agent Model Select宽度**：按钮按图标、模型名和chevron的实际内容宽度收敛，不拉伸填满Composer Grid第一列；短名称不留空白，长名称只在超过可用列宽时ellipsis。图文与chevron间距保持`6px`，chevron右侧内边距`7px`。
- **WebSocket消息状态**：Messages列表加载、无数据消息、加载失败时保留已有边框和方向工具栏；状态区最小高度`116px`，用flex双轴居中，内容内边距`12px`，文字`12px/1.6`、`--text-3`，长错误文本可换行。普通消息行、消息payload与断点界面不变；仅Ping/Pong/Close的连接可以没有数据消息。

- **Settings / Storage**：标题同行最右侧放`30px` Refresh图标按钮和Tooltip，操作期间阻止重复点击；标题不重复显示容量badge，Maintenance不再有Refresh usage行。Usage仅一行`Captured body data`，说明包含内存和临时文件中的正文，不显示Capture database、Response bodies或Total on disk；Contents保留Session/Exchange/正文数量。Clear capture旁明确它与Capture列表清空是同一操作、记录和正文一起删除、导出文件和录制状态保持，原位置提供Cancel/Confirm clear。沿用现有Settings分组与行，清理行允许自然换行，不新增Memory/Disk/Retention配置或自动轮询。读取失败显示Unavailable而非0 B，默认Storage页与正常/确认/清空/不可用八张明暗图一一对应。
- **Settings / Updates**：Version与Delivery按自然流排列。说明分别为`Stable releases from GitHub. Downloads start only when you choose.`、`Newest stable release`、`Stable release channel`；固定来源名称不变，不宣称仓库公开。Check、Download、Open installer、进度、失败重试与通知沿用原控件、字号、间距和主题；404或请求失败显示Failed，不要求登录。
