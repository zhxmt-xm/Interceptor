# 组件规范：Capture 与 Inspector

> 返回 [设计系统索引](README.md)

- **Inspector**：**默认关闭**，点击任一请求行才开启，摘要 box 右侧的 Close 关闭后 list 占满剩余宽度。整个 Detail 区域从 method 行到 Tabs、正文都使用 `--panel`，不得出现灰色衬底。头部 method chip + 语法着色 URL（`dom`=text-2 / `path`=text）+ 右侧状态 pill（如 `200 OK` 绿）保持原内容结构，并由独立白色 Request 摘要 box 包裹。外层行与 box 都使用 `40px` 高度，顶部距窗口 Header 留 `10px` 呼吸间距（不再与左侧工具栏强行同轨）；box 左右外间距均为 `14px`，横向 padding `8px / 18px`、`gap:10px`，内容垂直居中。box 使用 9px 圆角和两层无方向偏移的均匀浅阴影，不使用 solid border；阴影四周必须完整，不得由工作栏、splitter、Tabs 或 overflow 裁切。box 与 Tabs 之间使用普通文档流 `6px` 间距，Detail 区域不使用定位、浮动或 `z-index` 拼接。页签为 `Headers / Request / Response / Timing / Cookies / TLS`。Detail 内小节标题使用高对比 `--text-2`、700 weight、左侧 2px accent 标记与向右渐隐短线，不能只靠浅灰大写字。Headers 分区 `General / Response Headers / Request Headers`（`kv` 栅格 `168px / minmax(0,1fr)`，key `--text-2` mono、value `--text` mono，特殊值用 `--accent`/`--green`）；KV key/value 使用 `18px` 行高。可复制 value 的 inline action 在行 hover 时显示，使用 `18×18px` 按钮和 `14×14px` 图标，不增加水平或垂直偏移；具体排列与长值换行遵循下方「KV 值与 Copy」。`Cookie`/`Set-Cookie` 不在 Headers 重复出现，只归入 Cookies tab。Body 预览的档位、工具行与各类型视图见下方「正文预览档位矩阵」；任何档位不得横向撑开 Inspector。Timing 只显示持久化的真实 Waiting(TTFB)/Response body 时间段，不伪造 DNS/TLS 阶段。内容区 `overflow-y:auto` 可滚。
- **KV 值与 Copy**：保留原文字可用宽度和自然换行，每条可视行使用inline-flex与`align-items:center`；规则marker和Copy以4px gap紧跟最后一行，不再对齐整个多行文字块。连续文字选择、失效值删除线和Rule跳转保持，marker文字隔离祖先删除线；复合Status/Client Application继续原有内容结构。共享IconButton的inline档管理18px按钮/14px图标/5px圆角、padding0和图标不收缩；仅行hover时显示，隐藏仍占位，不换字体/行高、不加位移、不把Copy移到key列。
- **Inspector URL就绪状态**：标题保留host/path显示；当前选中请求的完整URL未就绪时不渲染标题Copy，General的Request URL也不复制短标题。就绪后恢复现有Copy外观与hover，不增加额外取数或替代URL；切换请求不能使用上一条详情提前显示Copy。
- **WebSocket消息正文**：由外层消息行控制展开/收起，内部保留`Received text`、大小/消息序号与Copy普通元数据行。正文复用Pretty/Tree/Raw/Hex、MIME与Save/Copy/Fullscreen，FullScreen打开同一消息并保留模式，关闭后不切换档位。正文外层使用11px/12px/15px padding与9px标题下方间隔；Compact代码外框以Monaco内容高度加实际边框计算，不重复预留水平滚动条。普通展开消息采用下方的限高与resize规则；规则Text/File、断点Original body与普通填充预设不变。
  - Tree沿用产品key/冒号、条目数与独立折叠槽，内联按展开行定高、全屏填充容器；Copy保留原文，Pretty Copy为格式化JSON。Hex按容器和实际1ch宽度重排显示，48px窗口保留滚动，Copy仍为完整16字节格式。全屏代码保持内容高度，工具栏保留MIME/Save，头部提供Copy/Close；不将WebSocket全屏替换为其他HTML示例。
- **gRPC/WebSocket普通展开消息的compact Monaco**：初始高度为`min(内容高度, 所属滚动容器可用空间)`，短正文保持自然高度；不把评审样例的441px或128px设成固定上限。右下角使用原生CSS `resize: vertical`，Monaco内滚动到边界后由外层继续滚动（`alwaysConsumeMouseWheel: false`）。窗口缩小时按可用空间clamp，恢复后还原用户拖高；隐藏初始化、字体加载和换行重排不视为用户拖拽。
  - 普通消息的Monaco启用组件级`resizable`；保留`12px`字号、`20px`行高、上下`13px`padding与实际边框，最小高度为一行加padding与边框。标题、模式、MIME、Save、Copy与Fullscreen控件不变，Copy不受可见高度影响。HTTP Original/File另按下方HTTP正文规则；Hex、Tree、全屏、Composer和其他Monaco维持原设计。
- **HTTP断点Original/File/Text**：Original正文沿用`12px/20px`与上下`13px`padding、实际边框，左侧使用共享Monaco的`16px`槽；初始高度为内容与所属滚动容器可用空间的较小值，短内容自然高度，支持右下角原生vertical resize与内外滚轮交接。File取消旧104px上限，预览使用无内层边框的同一`12px/20px/13px`规格，文件头下、正文上保留`Preview only. Forward edited uses the complete selected file, not the visible preview.`。
  - Text保留受控Ant TextArea、现行`autoSize: { minRows: 4, maxRows: 8 }`及完整value，不加`maxLength`；上方增加完整文本说明。Composer请求与响应继续填充面板，不增加resize或常驻自动格式化提示。普通gRPC/WebSocket及其现有断点设计不因该HTTP外壳规则变化。
  - 格式化/截断提示位于Original工具栏下或File完整文件说明下、Monaco上方，复用`1px --border`、8px圆角、`--panel-2`、11.5px文案、14px Lucide图标及既有Format按钮。大小由实际总字节数与预览字节数生成；完整≤1 MiB自动格式化、完整1–2 MiB手动，截断禁止格式化，图片独立16 MiB。正常自动格式化不新增常驻提示；明确展示自动格式化策略的设计态保留已确认说明。Original按真实MIME保留JSON高亮，File保持plaintext；不为fixture去除产品既有语法高亮。失败在同位置显示`Formatting failed. The original content is unchanged.`，原文保持，不把失败当成功。
- **分组标题附加内容**：公共`CollapsibleSection`、普通`.sh`与产品`SectionHeader`统一`min-height:36px`，展开和折叠保持同一下限；较高内容可自然撑开，不设固定高度。`count`放普通计数和MIME文字，chevron槽为13px；`labelExtra`放可点击规则证据等交互附加内容，保留24px操作槽。标题及附加内容均由父flex居中，HTTP/WebSocket Replacement不另设局部高度。
- **规则 Header 效果**：Inspector 同时展示规则前后的 header 证据。`set` 的生效新值标记绿色 `Rule set`，被替代旧值保留、加删除线并标记黄色 `Rule replaced`；`append` 只标记新增值，使用蓝色 `Rule appended`；`remove` 保留被删除旧值、加删除线并标记红色 `Rule removed`。Request 效果表示代理发给上游的值，Response 效果表示浏览器实际收到的最终响应；marker 使用 18px 高紧凑标签，与 KV 文本共享垂直中线，并固定距前值 `4px`，不新增独立列。标准 HAR 不导出 marker/历史值，Native Archive 保真保存。
- **HTTP 断点 Header 编辑**：保留30px高的name/value输入框，比例`0.82fr / 1.18fr`，删除列按按钮实际宽度占位；所有行的输入框边界一致，普通行间距6px。`Rule set`/`Rule appended`不占独立列，改为value输入框下方2px的右对齐说明，字号9px、500 weight、行高12px，保留对应语义色，不画标签边框或底色。无effect行不保留说明空行，带effect行总高44px；行组与Add header之间仍为8px。普通Inspector的Header marker和WebSocket握手编辑保持各自既有设计，不套用此样式。
- **规则 Body 效果**：Body section标题后紧跟可点击`Rule replaced` marker（与Header replace同一黄色语义）和中性`Text/File`来源chip，chevron最右；MIME/大小只在BodyViewer工具栏显示，不在标题重复。展开区顶部使用独立`Body version · Original / Final`证据栏，默认Final；Request两档可切，Response Original disabled并显示`Original response body is unavailable`，不得把空正文冒充原文。BodyViewer的MIME/大小、Copy、Save与Fullscreen都跟随当前档。Final writer覆盖早期writer，只显示一组marker；标准HAR只保留Final，Native Archive保真。
- **Rules action tags**：Rule row 按 action 声明顺序派生去重后的 tags，只内联显示前两个；存在更多 tags 时紧接一个 `22×22px`、Lucide `Ellipsis` `14×14px` 的可聚焦按钮。tags 容器必须使用 `align-items:center`：tag 保持由 `10px/600`、`padding 2px 6px` 形成的约 `16–17px` 自然高度，不得被 flex 默认 `stretch` 拉成按钮的 `22px`；tag 与按钮按各自 border box 的垂直中心对齐。按钮 hover/focus 使用 `--hover` 底，Ant Tooltip 在 hover/focus 下按原顺序展示全部 tags；tag `radius 6px`、组内 `gap 5px`。入口不得改变 rule selection、open editor、enabled 或 drag 状态，三级目录窄宽度下 row 也不得横向溢出或遮挡 hit count。
- **Capture / Rules 联动**：Capture 请求行右键菜单按 Rules 的 Action 分类（Rewrite / Serve & reroute / Traffic / Control）快速创建规则草稿；新草稿使用当前请求完整 URL 的 exact matcher，只打开 Rules editor，不自动 Apply。Capture 的 Rule 筛选位于筛选分栏的 `Rule` 分组，多个 Rule 按 OR 匹配。Rules editor 顶栏提供漏斗图标，一键切回 Capture 并在筛选分栏里选中该 Rule。Inspector 的 Rule marker 是可点击按钮，点击直达产生该 effect 的 Rule detail；规则已删除时保留历史 marker，但不伪造可达详情。- **Composer 工作区**：横向为 `Collection 分栏 / splitter / 工作区`，工作区纵向依次为 `40px 文档标签条 · 56px URL 行 · 请求编辑区(minmax(0,1fr)) · splitter · 368px 响应区`。全 feature 只有这两道 splitter，与 Capture 同数量、同实现；其余分区一律用单条 `1px --border`，不叠加多余横线。
