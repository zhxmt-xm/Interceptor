# M14 临时 Capture Session 与轻重数据分层

> 状态：已完成

> 产品详细设计：[桌面网络调试代理完整方案.md](桌面网络调试代理完整方案.md) 第十二、十四章和第二十七章 M14

## 阶段目标

把 Capture 从跨进程持久历史库改为当前 Core 代际的临时工作集：Stop 真正停止 Mockttp listener 但保留已有记录，Start 创建新 Recording Session 并继续追加，只有 Clear 或 Core 退出才释放 Capture。Renderer 持有全量轻量 summary，Core 持有按需详情、正文和 WebSocket/gRPC 重内容；RuleSet 与 Diagnostics 独立持久化。

## 数据所有权

| 数据 | 所有者 | 生命周期 |
| --- | --- | --- |
| `CaptureExchangeSummary[]`、过滤、选择、滚动、Inspector tab/宽度 | Renderer Zustand | 当前 Core 代际；切换 feature 与 Stop/Start 保留，Clear/Core 重启清空 |
| Exchange detail、ordered headers/trailers、连接/Timing 元数据 | Core `TemporaryCaptureStore` | 当前 Core 代际；Stop/Start 保留，Clear/Core 退出释放 |
| Request/Response body、WS/gRPC payload | Core `TemporaryBodyStore`（内存 + 有界 spill） | 当前 Core 代际；Stop/Start 保留，Clear/Core 退出物理删除 |
| RuleSet revision/definitions | 独立持久 Rule Store | 跨 Recording/重启 |
| RuleHit | Core `TemporaryCaptureStore` | 跟随所属 Exchange；Clear/Core 退出释放 |
| Diagnostics | 独立 `diagnostics.sqlite` Worker | 按既有保留策略持久化 |

Renderer 不持有正文、完整敏感 header、Blob path、数据库句柄或文件系统能力。Tree list 使用全量 summary，不要求把完整 Exchange 搬进 React。

## 目标结构

- `storage/entry.ts` 直接组合 `TemporaryCaptureStore`、`TemporaryBodyStore` 和 `RuleStore`，没有常驻 Storage Worker。
- Capture 使用 `Map` + 惰性 `(startedAt, seq)` 有序索引与 opaque cursor；不创建运行时 `capture.sqlite`。
- RuleSet 由 Core 低频直接读写 `rules.sqlite`；首次启动从旧 `capture.sqlite.rule_set` 迁移后删除旧 Capture 文件。
- Body 小于阈值留内存，较大正文异步 spill 到 `capture-temp/`；Clear/Core 退出清理目录，Stop 保留。
- Native archive 每次导入/导出单独启动 `archive/host/entry.ts` + `archive/worker/entry.ts`，按 100 条批次读写兼容 SQLite snapshot，完成/取消/失败后退出。
- Import/export 命令到达 Core 后直接读取当时 Store 内容；Renderer 用全屏 Loading 阻止正常操作，只保留 Cancel，不增加 Core action 门禁。
- Renderer 的 Capture 管线常驻 App，分批同步当前 Core 的全部 summary；过滤只在 Renderer 派生，不传完整 header/body。

## 已完成实施

- Capture feature 往返已保留 selected request、scrollTop、Inspector tab 与 splitter 宽度。
- 默认 HTTPS 不生成/信任 CA；Core TLS passthrough 仅记录有限 tunnel metadata，用户从 Detail 显式完成 CA/Trust/Start decrypting。
- Stop 真关闭 Mockttp listener 与 WebSocket bridge，旧端口拒绝连接，但 Core/Renderer 记录保持；Start 新建 Session 后继续追加。
- Clear 是唯一用户删除入口：直接清空 Core/Renderer 与临时 spill；Core 重启也释放全部临时数据。
- Body preview 已覆盖常见文本 MIME、未知 UTF-8 内容探测和四模式切换；Hex 按容器宽度重排。
- Timing 使用 Mockttp 真实 `headersSentTimestamp` / `responseSentTimestamp`，不伪造 DNS/TLS 阶段。

## 风险与约束

- 不采用“完整 request 全放 Renderer”：正文与敏感 header 会增加 Renderer 内存、暴露面和高频重渲染风险。
- 内存 Store 必须保持 10 万行有序分页无重复/缺失；Renderer 继续用虚拟列表，不创建 10 万个 DOM。
- Temporary Body Store 不能纯内存承载 64 MiB × 多请求；保留总配额、单体上限和 spill。
- Archive 导入/导出仍把输入视为不可信攻击面，所有既有 ZIP path/size/hash/ratio 校验必须保留。
