## 阶段目标

在 Electron Main 与独立 Proxy Core 之间建立本地、认证、版本化、有背压的正式通信基座，并通过窄 Preload API 打通一条 Renderer 到 Core 的命令和事件路径。

M1 不实现 HTTP 代理、Traffic Session、正文存储或业务规则。

## T1.1 范围

### 必须覆盖的消息族

- Protocol envelope、schema/version 标识和 capability negotiation。
- Handshake request/response 与不兼容版本拒绝。
- Command request、correlation ID、success/error response。
- 批量 Capture Event notification 的通用封装；此阶段不定义完整 HTTP Exchange 业务字段。
- 分页 Session Query request/response 的分页和稳定游标结构。
- Body Range request、chunk metadata 和结束/错误状态。
- Rule validate/replace/revision lifecycle 的协议外壳。
- Core health、metric、diagnostic 和 graceful shutdown 的正式模型。

### 需要明确的兼容规则

- package 和 protocol version 的语义及协商算法。
- enum 零值必须表示 unknown/unspecified，不能承载业务默认行为。
- 已发布 field number/name 的保留策略。
- optional/oneof、未知字段、默认值和新增字段的向前/向后兼容行为。
- ID、timestamp、sequence、cursor、byte offset/length 的统一表示。
- 可重试、不可重试和协议错误的结构化分类。
- 消息与 frame size 上限由协议声明；实际 enforcement 在 T1.2/T1.3。

### 建议交付结构

```text
packages/protocol/
  package.json
  tsconfig.json
  proto/
    envelope.proto
    handshake.proto
    command.proto
    event.proto
    query.proto
    body.proto
    rule.proto
    health.proto
  src/
    generated/
    index.ts
  tests/
```

实际文件拆分可根据所选 generator 调整，但 schema 必须按领域职责组织，不能形成单个无边界巨型文件。

### T1.1 验收标准

- Protobuf compiler/runtime 和生成器版本精确锁定，Node 24/TypeScript 7 下可重复执行。
- `npm install` 后一个仓库命令即可重新生成，不依赖未记录的全局工具。
- Desktop 和 Proxy Core 可引用协议 package，不引入循环依赖。
- 代表性消息 encode/decode round-trip 通过。
- 未知字段、缺少必要语义、不兼容版本、非法 ID/range 的行为有测试。
- 生成代码策略明确：若提交生成物，CI/测试必须能检测 schema 与生成物漂移；若不提交，build 必须先可靠生成。
- `npm run typecheck`、协议单测和 `git diff --check` 通过。

## T1.2 边界

- Windows 使用当前用户可访问的 Named Pipe；macOS 使用用户私有 Application Support 目录下权限 `0600` 的 UDS。
- 不使用普通 localhost TCP，避免端口抢占或未认证探测。
- Main 每次启动生成随机 token，通过受保护的 Core 启动参数/环境传递；日志不得输出 token。
- frame 使用明确长度前缀和最大尺寸，处理 partial read、coalesced frame、EOF 和 malformed length。
- 认证完成前不能接受业务消息。

## T1.3 边界

- 每个 subscriber 使用有界 queue。
- progress、byte count 等高频中间态可合并；最终 Exchange state、error、RuleHit 不得丢失。
- 慢消费者不能阻塞 Core 网络数据面；无法消费必要消息的 client 断开并记录诊断。
- correlation 必须处理 timeout、cancel、late response、duplicate ID 和断线清理。

## T1.4 边界

- Preload 仍只暴露面向意图的 API，不提供通用 IPC send。
- echo 只用于验证 transport 和 contract，不演化为任意消息逃生口。
- event subscription 必须返回 unsubscribe，并验证窗口销毁后的 listener 清理。
- packaged smoke 增加正式通道的最小往返和退出清理断言。
