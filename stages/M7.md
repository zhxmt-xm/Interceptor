### Server（进行中）——T7.1 规则持久化 + handler

- **schema v2** `storage/worker/worker-schema.ts`：新增单行 `rule_set` 表（`id` CHECK=1、`revision`、`rules_json`、`updated_at`），`CAPTURE_SCHEMA_VERSION=2`，只向前迁移追加。
- **CaptureStore** `storage/worker/worker-store.ts`：`loadRuleSet()` 空库返回 revision 0 空集；`saveRuleSet(expectedRevision, rules)` 在单事务内读-比较-写，`expectedRevision` 不等于当前 revision 抛 `RuleRevisionConflictError`，否则 UPSERT 写入 revision+1 并返回新集。rules 以 JSON 序列化，绝无 callback/运行时对象。
- **存储链路**：host↔worker 协议 `storage/protocol.ts` 新增 `save-rule-set`/`load-rule-set` 请求与 `RuleSet` 结果映射；`worker-request-dispatch.ts` 分派；`StorageWorkerHost`/`StorageService` 逐层转发 `saveRuleSet`/`loadRuleSet`。
- **语义校验** `core-protocol/validation.ts`：导出 `collectRuleDiagnostics(rules): ProtocolDiagnostic[]`——重复 rule id、regex matcher 可编译性、status 区间 min≤max、JSON body 可解析；wire 校验之外的跨字段/运行时检查，供 rules.validate/replace 复用，Renderer 经命令获取。
- **handler** `core-application.ts`：`rules.validate` 纯语义校验返回 `{valid,diagnostics}`（无 I/O）；`rules.get` 经 storage `loadRuleSet` 返回 ruleSet；`rules.replace` 先语义校验（不通过→invalid-message），再 `saveRuleSet` 乐观并发，`RuleRevisionConflictError` 映射为 `conflict`（retryable）。
- **单测**：CaptureStore 规则集空库/往返/revision 递增/冲突不改状态；`collectRuleDiagnostics` 五类语义诊断；worker-database schema v2 + rule_set 表检查；core-application 未实现命令示例改用 breakpoint.resolve。typecheck 三 workspace + test:unit 121 passed 全绿。

### Server（进行中）——T7.2 Matcher 编译器

- `rules/matcher-compiler.ts`：`compileMatcher` 把每种 RuleMatcher 编译为 `(MatchContext)=>boolean` 纯判定；`compileRuleMatchers` 组合为 AND；`requiresResponsePhase` 标记含响应侧 matcher 的规则供引擎按阶段调度。
- 语义：method/host/header 名/MIME 大小写不敏感，path/url/header 值/query 敏感；host/path/url 支持 exact/wildcard/regex，query/header 支持 present/exact/regex（多值 header/query 任一命中即真）；status 仅响应阶段判定；mime 支持 `*` 通配；非法 regex 防御性恒不匹配。
- 单测 `rules/tests/matcher-compiler.test.ts`（12）：各 matcher 类型、大小写、多值、通配、响应阶段缺失、AND 组合、requiresResponsePhase。

### Server（进行中）——T7.3 Header/Query Action

- `rules/action-executor.ts`：`applyRequestAction`/`applyResponseAction` 对中立可变状态（MutableRequestState/MutableResponseState）套用 RuleAction。请求侧处理 phase=request 的 header（set/append/remove）与 query（set/remove），响应侧处理 phase=response 的 header；set 覆盖大小写变体同名头、append 合并为数组、remove 不敏感删除、query 经 URL.searchParams 改写并回写 url。
- **审计安全**：ActionSummary 只记 action 类型 + 目标 name，绝不记 header/query value，避免 Authorization/Cookie/Token 写入 rule_hit；无改动/无值返回 null，不产虚假 hit。
- 其余 action（body/synthetic/block/status/breakpoint）返回 null，留 T7.4–T7.6。
- 单测 `rules/tests/action-executor.test.ts`（14）：header set/append/remove 大小写与多值、阶段隔离、query set/remove、缺值与未实现 action 返回 null。

### Server（进行中）——T7.4 Body / Synthetic / Map Action + Contract map 扩展

- **Contract 扩展** `core-protocol/rules.ts`+`validation.ts`：RuleAction 新增 `map-local`{path} 与 `map-remote`{scheme?/host?/port?/path?}；wire 校验（scheme enum、port 范围、bounded path）+ collectRuleDiagnostics 语义诊断（map-local 含 `..` 穿越→unsafe-map-path；map-remote 全空→empty-map-remote）。
- **action-executor 重构** `rules/action-executor.ts`：返回值从 `ActionSummary|null` 升级为 `ActionOutcome`（none/mutated/respond/block），applyRequestAction 异步（map-local 读文件）。
- **body**：text/json 替换请求/响应 body。**synthetic**：短路 respond（statusCode + headers + body）。**map-remote**：按 scheme/host/port/path 覆盖改写请求 URL。**map-local**：`path.resolve` 规范化 + 允许根白名单校验（在根内才服务，`..` 穿越/超出根/无根一律 fail-safe 返回 none），命中读文件 respond 200（按扩展名猜 content-type），缺失 respond 404。**block**：respond block outcome。
- **审计安全**：ActionSummary 仍只记 action + 目标名，不记 body/value。
- **单测** `rules/tests/action-executor.test.ts`（21）：header/query（适配 ActionOutcome）、body 请求/响应、synthetic、map-remote、map-local 允许根内/无根/穿越/缺失、block；临时目录真实文件系统验证路径安全。

### Server（进行中）——T7.5 Status 覆盖 / Delay / Throttle + block

- **Contract 扩展** `core-protocol/rules.ts`+`validation.ts`：RuleAction 新增 `delay`{phase,ms} 与 `throttle`{phase,bytesPerSecond}；常量 MAX_RULE_DELAY_MS=300s、MIN/MAX_RULE_THROTTLE_BPS；wire 校验 phase enum + ms/bps 范围。
- **action-executor** `rules/action-executor.ts`：ActionOutcome 新增 delay/throttle kind（附加流控，不短路，由引擎累积）。status action 在 applyResponseAction 覆盖 state.statusCode（mutate），请求侧 status 返回 none；delay/throttle 按 phase 在对应阶段产出流控 outcome，phase 不匹配返回 none。block outcome 已于 T7.4 就绪，实际连接 reset/close 在 T7.7 引擎生效。
- **单测** `rules/tests/action-executor.test.ts`（26）：新增 status 覆盖/请求侧忽略、delay 请求·响应·phase 不匹配、throttle 匹配相位。

### Server（进行中）——T7.6 Breakpoint 状态机

- **Contract 扩展** `core-protocol/messages.ts`+`validation.ts`：BreakpointEdit（method/url/statusCode/headers/body）；breakpoint.resolve payload 加可选 edit；BreakpointResolutionResult state 加 'edited' + wire 校验。
- **BreakpointQueue** `rules/breakpoint-queue.ts`：suspend(phase,timeoutMs,timeoutPolicy) 返回 {id, Promise<BreakpointOutcome>}，timeoutMs 到期自动 timed_out（带 timeoutPolicy 兜底）；resolve(id,action,edit) → continued/edited/dropped/timed_out，未知/已解除返回 null；closeAll 断线/退出确定性关闭全部为 timed_out；list/size 供状态。所有解除经 finish 统一清 timer + settle。
- **接入** `core-application.ts`：持有 BreakpointQueue（bootstrap 创建），breakpoint.resolve handler 经 withBreakpoints 调 resolve（未找到→conflict），requestExit 统一 closeAll。
- **单测**：breakpoint-queue（8）continued/edited/dropped/超时自动/closeAll/未知/重复/取消超时；core-application breakpoint.resolve 无 queue→internal。
- **待 T7.7**：rule-engine 在 beforeRequest/beforeResponse 命中 breakpoint action 时 suspend + await outcome，据 state 放行/应用 edit/丢弃；命中事件推送 Renderer。

### Server（完成）——T7.7 规则引擎接入 proxy-service + 热切换 + RuleHit 落库

- **rule-engine** `rules/rule-engine.ts`：持有 ruleSet 引用 + 编译缓存；setRuleSet 原子替换（过滤 enabled + priority/id 排序 + 编译 matcher），热切换不 reset server；evaluateRequest/evaluateResponse 按序对匹配规则执行 action，聚合 mutate/respond/block/delay/throttle + breakpoint（suspend+await，edited 应用 edit、drop→block），产出 RuleHitRecord。
- **proxy-service 接入**：单 `forAnyRequest().thenPassThrough` 的 beforeRequest/beforeResponse 调 engine；continue→返回改写(method/url/headers/body 或 statusCode/headers/body)，respond→短路响应，block→'reset'/'close'，delay→await。按 request id 暂存 hits，captureExchange 关联 exchange id 后写 rule_hit。引擎异常不阻断转发。Mockttp 回调用本地结构类型（不依赖其非公开导出）。
- **热切换** core-application：bootstrap 创建 RuleEngine(breakpointQueue) 注入 proxy-service；存储就绪后 loadRuleSet 热加载；rules.replace 成功后 setRuleSet 原子替换。
- **RuleHit 落库** storage：schema v1 rule_hit 表 + CaptureStore.appendRuleHits + host/service/协议链路。
- **单测** `rules/tests/rule-engine.test.ts`（10）：匹配改写+hit(含 revision)、非匹配/disabled 跳过、priority 排序、synthetic 短路、block、delay 累积、断点 continue/drop/edited、响应侧 status 覆盖。
- **已知限制**：throttle 带宽限速 Mockttp 未提供流控原语，evaluation 已聚合 throttleBps 但暂未在数据面实际限速（记为后续原生增强）；断点命中事件推送 Renderer 待 M8 UI。
