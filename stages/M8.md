### T8.2 Composer（已完成）

**Server（出站请求执行）**
- `proxy-core/composer/composer-service.ts` 新增 `ComposerService.send()`：用 Node `http`/`https`（HTTP/1.1，auto/http/1.1）或 `http2`（h2）执行请求，返回状态/头/有界正文（1 MiB 上限对齐 MAX_BODY_CHUNK_BYTES）/时序 + 真实 TLS（protocol/cipher/alpn/subject/issuer/valid）与 remoteAddress；网络错误以 `ok=false + error` 返回不抛出。允许自签证书（rejectUnauthorized=false，调试用途）但如实回传证书信息。
- `core-application.ts` 持有 `ComposerService` 实例，新增 `composer.send` handler（`diagnostics.action('composer.send')`）。

**Contract（composer.send 命令）**
- `core-protocol`：`messages.ts` 新增 `ComposerSendCommand`/`ComposerResponseResult`/`ComposerTlsInfo` + union + `CoreResultForCommand`；`validation.ts` 加 composer.send 命令（method/url/headers/body/protocol/timeoutMs）与 composer.response 结果（status 0–599、byteArray body、TLS 对象或 null）wire 校验；`core-rpc-client.ts` 加映射；`protocol.test.ts` 加 composer.send 接受 + 结果/非法 status 校验（14 tests）。
- 窄 API：`desktop-api.ts` 导出 `ComposerTlsInfo` + `ComposerRequest`/`ComposerResponse` 类型 + `composer:send` channel + `sendComposerRequest` 接口；`preload.ts` 桥接；`main.ts` handler（`toComposerRequest` 边界校验）；`renderer-utils.ts` 加 `toComposerRequest`。

**Client（数据驱动 Composer，1:1 保持设计视觉）**
- `composerStore.ts`（Zustand：method/url/protocol/headers(可开关)/body/auth/请求·响应 tab/response/history/sending；`buildSendHeaders` 合并启用 header + Auth 派生 authorization；`parseQueryParams` 从 URL 解析查询）；`useComposer.ts`（`sendComposerRequest` 组装并调窄 API）。
- UI：`RequestBuilder`（method Select + URL 受控输入 + Send + Protocol Segmented（Auto/HTTP1.1/HTTP2→auto/http1.1/h2）+ TLS 信息 + Headers/Query/Body/Auth 四标签全可编辑）、`ResponsePanel`（状态 Chip 着色 + statusText + 耗时/大小/协议 + Body(JSON 美化)/Headers/Cookies/Raw 标签 + 空/发送中/错误态）、`ComposerTopbar`（History 下拉可载入历史 + New 重置）、`ComposerStatusbar`（Ready/Sending/Failed + remoteAddress + last send）；删除硬编码 `data.ts`。
- 共享原语扩展：`Chip` 增 `red`/`yellow` 色调（响应状态）。
- **header 兼容任意字段**：Composer header/query 名与值均自由输入。

**验证**：`npm run typecheck` 三 workspace 通过；`npm run build:core` + `npm run test:unit` 通过（Desktop 36 / Proxy Core 139 含 countRuleHits 聚合 + 真实 worker 集成 / Core Protocol 14）。
- **已知限制**：`protocol: 'auto'` 当前走 HTTP/1.1（完整 ALPN 自动协商回退为后续增强）；Composer 请求为直接出站（不经代理管线/规则），Replay/基于捕获会话构造为后续。

### T8.3 Breakpoint 编辑 UI（已完成）

**Server（断点快照 + 查询/开关）**
- `rules/breakpoint-queue.ts`：`suspend` 增可选 `BreakpointSnapshot`（ruleName/method/url/statusCode/headers/body）与 `deadline`（createdAt+timeoutMs），`list()` 返回快照与 deadline 供 UI。
- `rules/rule-engine.ts`：新增全局 `breakpointsEnabled` 开关（关闭时命中 breakpoint action 立即 continue 不挂起）；`awaitBreakpoint` 从可变 state 构建请求/响应快照（bag→pairs、body 解码限 256 KiB）传入 suspend。
- `core-application.ts`：`breakpoint.list` handler（映射队列快照 + enabled）、`breakpoint.configure` handler（设 engine 开关）。

**Contract（breakpoint.list / configure）**
- `core-protocol`：`messages.ts` 新增 `BreakpointListCommand`/`BreakpointConfigureCommand`/`PendingBreakpoint`/`BreakpointPendingResult`/`BreakpointConfigResult` + union + `CoreResultForCommand`；`validation.ts` 加命令与结果 wire 校验（phase 枚举、headers 数组、statusCode 范围）；`core-rpc-client.ts` 加映射；`protocol.test.ts` 加 breakpoint.list/configure 接受 + pending 非法 phase 校验（15 tests）。
- 窄 API：`desktop-api.ts` 导出 `BreakpointEdit`/`PendingBreakpoint` + `BreakpointsSnapshot` + `breakpoint:list/resolve/configure` channels + `listBreakpoints`/`resolveBreakpoint`/`setBreakpointsEnabled` 接口；`preload.ts` 桥接；`main.ts` 3 个 handler（`toBreakpointEdit` 边界校验 + action 枚举校验）；`renderer-utils.ts` 加 `toBreakpointEdit`。

**Client（数据驱动 Breakpoints，轮询暂停队列，1:1 保持设计视觉）**
- `breakpointsStore.ts`（Zustand：breakpoints + enabled + selectedId + 编辑草稿（保 poll 期间不覆盖用户编辑）+ `buildEdit`/`formatCountdown`）；`useBreakpoints.ts`（1s 轮询 `breakpoint.list`、`resolveSelected` continue/drop/edited、`continueAllBreakpoints`、`setBreakOnMatch`）。
- UI：`PausedQueue`（真实暂停队列 + method/status + ruleName + url + 倒计时 + Continue all + 空态）、`BreakpointEditor`（method/status Chip + url + 阶段徽标 + 倒计时 + 可编辑 headers/body + Drop/Continue unmodified/Execute edited）、`BreakpointsTopbar`（真实 paused count + break-on-match 开关）、`BreakpointsStatusbar`（paused + break-on-match on/off）；删除硬编码 `data.ts`。
- **方案说明**：采用**轮询** `breakpoint.list`（而非新增 push 事件通道）驱动暂停队列——更简单稳健；请求在 Core 侧 await 挂起，1s 轮询延迟可接受。
- **header 兼容任意字段**：断点编辑 header 名/值自由输入。

**验证**：`npm run typecheck` 三 workspace 通过；`npm run build:core` + `npm run test:unit` 通过（Desktop 36 / Proxy Core 139 / Core Protocol 15）。
