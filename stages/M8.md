## 实现记录

### T8.1 Rules workspace（已完成）

**Server（rule hit 聚合查询）**
- `storage/types.ts` 新增 `RuleHitCount{ruleId,count}`；`worker-store.ts` 新增 `countRuleHits()`（`SELECT rule_id, COUNT(*) ... GROUP BY rule_id`）。
- 存储链路：`storage/protocol.ts` 新增 `count-rule-hits` 请求 + 结果映射，`worker-request-dispatch.ts` 分派，`host-worker.ts`/`storage/entry.ts` 逐层转发。
- `core-application.ts` 新增 `rules.hits` handler（`diagnostics.action('rules.hits')` → `countRuleHits`）。

**Contract（rules 窄 API + rules.hits 命令）**
- `core-protocol`：`rules.ts` 新增 `RuleHitCount`；`messages.ts` 新增 `RulesHitsCommand`/`RulesHitsResult` + union + `CoreResultForCommand`；`validation.ts` 加 `rules.hits` 命令（空 payload）与结果（counts 数组，ruleId 有界 + count 非负）wire 校验；`core-rpc-client.ts` 加结果类型映射；`protocol.test.ts` 加 rules.hits 命令接受 + 结果/非法校验（13 tests）。
- 窄 API：`desktop-api.ts` 导出规则类型（RuleSet/RuleDefinition/RuleMatcher/RuleAction/RuleHeaderPair/RuleHitCount/ProtocolDiagnostic/RulePhase/StringMatchMode/KeyMatchMode/HeaderOperation）+ `RuleValidation`/`RuleReplaceResult` 类型 + `rules:get/validate/replace/hits` channels + `getRules/validateRules/replaceRules/getRuleHits` 接口；`preload.ts` 桥接；`main.ts` 4 个 handler（`assertTrustedSender` + `toCoreRuleDefinitions`/`assertRevision` 边界校验，replace 以结构化结果返回冲突/非法/错误避免 IPC 丢码）；`renderer-utils.ts` 加 `toCoreRuleDefinitions`（顶层结构+上限校验，深度语义由 Core wire 校验）与 `assertRevision`。

**Client（数据驱动 Rules workspace，1:1 保持设计视觉）**
- 共享原语扩展：`InputBox`（`value`/`onValueChange`/`placeholder`/`type` 受控输入模式）与 `Select`（`value`/`options`/`onValueChange` 受控原生下拉），保持既有只读展示模式向后兼容；`components/index.ts` 导出 `SelectOption`。
- 数据层：`rule-format.ts`（chip/match 派生、matcher/action 工厂、Select 选项表、诊断按规则聚合）；`rulesStore.ts`（Zustand：revision + 规则草稿 + selectedId + diagnostics + hits + dirty/saving/conflict/error + 增删改/排序/matcher-action 编辑）；`useRulesData.ts`（挂载加载规则集与命中计数、4s 轮询命中、去抖语义校验、applyRules 乐观并发 + 冲突重载）。
- UI：`RuleList`/`RuleRow`（真实规则 + 开关 + 派生 chips + 命中数）、`RuleEditor`（名称编辑 + 启用开关 + 删除 + MATCH 条件行 + ACTIONS 卡片 + Add condition/action + 校验栏）、`MatcherRow`（8 种 matcher 全类型受控编辑：method/host/path/url/query/header/status/mime）、`ActionEditor`（11 种 action 全类型受控编辑：header/query/body/status/synthetic/map-local/map-remote/block/delay/throttle/breakpoint）、`ActionCard`（通用卡片 + 6 色调 + 删除）、`RulesTopbar`（真实计数 + New rule + Apply changes dirty 感知）、`RulesStatusbar`（revision + enabled + 校验/冲突状态）；删除硬编码 `data.ts`。
- **header 兼容任意字段**：matcher/action 的 header/query name 与 value 一律自由 `InputBox` 输入（无写死枚举），操作/相位/模式为有限枚举 `Select`。

**验证**：`npm run typecheck` 三 workspace 通过；`npm run test:unit` 通过（Desktop 36 / Proxy Core 137 / Core Protocol 13）。packaged/parity 待 M8 收尾统一验证（Linux 环境 smoke 需 GUI、parity 字体差异不作严格门禁）。

### T8.2 Composer（已完成）

**Server（出站请求执行）**
- `proxy-core/composer/composer-service.ts` 新增 `ComposerService.send()`：用 Node `http`/`https`（HTTP/1.1，auto/http/1.1）或 `http2`（h2）执行请求，返回状态/头/有界正文（1 MiB 上限对齐 MAX_BODY_CHUNK_BYTES）/时序 + 真实 TLS（protocol/cipher/alpn/subject/issuer/valid）与 remoteAddress；网络错误以 `ok=false + error` 返回不抛出。允许自签证书（rejectUnauthorized=false，调试用途）但如实回传证书信息。
- `core-application.ts` 持有 `ComposerService` 实例，新增 `composer.send` handler（`diagnostics.action('composer.send')`）。

**Contract（composer.send 命令）**
- `core-protocol`：`messages.ts` 新增 `ComposerSendCommand`/`ComposerResponseResult`/`ComposerTlsInfo` + union + `CoreResultForCommand`；`validation.ts` 加 composer.send 命令（method/url/headers/body/protocol/timeoutMs）与 composer.response 结果（status 0–599、byteArray body、TLS 对象或 null）wire 校验；`core-rpc-client.ts` 加映射；`protocol.test.ts` 加 composer.send 接受 + 结果/非法 status 校验（14 tests）。
- 窄 API：`desktop-api.ts` 导出 `ComposerTlsInfo` + `ComposerRequest`/`ComposerResponse` 类型 + `composer:send` channel + `sendComposerRequest` 接口；`preload.ts` 桥接；`main.ts` handler（`toComposerRequest` 边界校验）；`renderer-utils.ts` 加 `toComposerRequest`。

**Client（数据驱动 Composer，1:1 保持设计视觉）**
- `composerStore.ts`（Zustand：method/url/protocol/headers(可开关)/body/auth/请求·响应 tab/response/history/sending；`buildSendHeaders` 合并启用 header + Auth 派生 authorization；`parseQueryParams` 从 URL 解析查询）；`useComposer.ts`（`sendComposerRequest` 组装并调窄 API）。
- UI：`RequestBuilder`（method Select + URL 受控输入 + Send + Protocol Segmented（Auto/HTTP1.1/HTTP2→auto/http1.1/h2）+ TLS 信息 + Headers/Query/Body/Auth 四标签全可编辑）、`ResponsePanel`（状态 Chip 着色 + statusText + 耗时/大小/协议 + Body(JSON 美化)/Headers/Cookies/Raw 标签 + 空/发送中/错误态）、`ComposerTopbar`（History 下拉可载入历史 + New 重置）、`ComposerStatusbar`（Ready/Sending/Failed + remoteAddress + last send）；删除硬编码 `data.ts`。
- 共享原语扩展：`Chip` 增 `red`/`yellow` 色调（响应状态）。
- **header 兼容任意字段**：Composer header/query 名与值均自由输入。

**验证**：`npm run typecheck` 三 workspace 通过；`npm run build:core` + `npm run test:unit` 通过（Desktop 36 / Proxy Core 139 含 countRuleHits 聚合 + 真实 worker 集成 / Core Protocol 14）。
- **已知限制**：`protocol: 'auto'` 当前走 HTTP/1.1（完整 ALPN 自动协商回退为后续增强）；Composer 请求为直接出站（不经代理管线/规则），Replay/基于捕获会话构造为后续。
