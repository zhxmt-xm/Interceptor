## 实施记录

### 关键决策

- **UI 已在 M0/T2.0 完成脚手架（`design/app` 一对一）**，M4 主要是把 mock 数据换成真实数据流，因此严格复用现有 CSS Module 类名与 DOM 结构，避免视觉回归；仅按需扩展基元（`MethodBadge` 接受任意 HTTP 方法、`StatusBadge` 增 red/info 语气）。
- **查询与实时事件共用 `CaptureExchangeSummary` 单行结构**（在 core-protocol 定义并被 storage 复用），使历史分页与 live tail 渲染同一行类型，避免重复定义；为列表显示补齐 `secure`（scheme==='https'）与 `durationMs`（completedAt−startedAt）。
- **Inspector 详情按需拉取**：新增 `sessions.detail` 命令返回 `CaptureExchangeDetail`（摘要 + URL + 请求/响应头 + 正文引用元数据），正文字节再经 `body.read-range` 按 blob hash 分块读取；详情为每次选择的**组件本地状态**，body/header 均不进入 Zustand 全局，符合内存约束。
- **过滤模型**：关键字/method/status/host 下推 Core（服务端过滤 + FTS），协议分段（H1/H2/WS）为客户端视图过滤（Core 无 protocol 过滤维度）；实时事件用 `matchesCoreFilter` 客户端谓词裁剪，保持 live tail 与当前过滤一致。
- **正文预览**：`BodyView` 文本类型（json/js/html/xml/text）用 CodeMirror（JSON 走 `@codemirror/lang-json` 高亮、只读、行包裹），非文本走 hex dump；单次预览上限 256KB，超出提示截断。

### 代码位置

- 数据层：`apps/desktop/src/renderer/features/capture/` 下 `captureStore.ts`（Zustand + `matchesCoreFilter`/`matchesSegment`）、`row-format.ts`（状态/协议/类型/大小/耗时映射）、`useCaptureData.ts`（订阅事件 + 过滤重查去抖 + 分页 `loadMoreSessions` + `toggleCapture` + `getCaptureStatus`）、`useExchangeDetail.ts`（选中拉详情，本地 state）。
- 组件：`RequestList`（虚拟化 + 分段 + Count + Clear 软清视图）、`RequestRow`（接 `CaptureExchangeSummary` + 虚拟定位）、`Omnibox`（真实 input + 结构化 pill + popover promote）、`CaptureTopbar`（录制开关 → `toggleCapture`）、`RequestInspector`（General/Headers/Request/Response/Timing/Cookies/TLS 接 detail）、`RequestInspector/BodyView.tsx`（CodeMirror + hex + 256KB 上限）。
- 窄 API：`shared/desktop-api.ts` 增 `startCapture`/`stopCapture`/`getCaptureStatus`/`querySessions`/`getExchangeDetail`/`readBody`/`onCaptureEvents` + `capture:*`、`sessions:query`、`sessions:detail`、`body:read-range` 通道；`preload/preload.ts` 桥接；`main/main.ts` IPC 处理 + 边界校验（`toCoreSessionQuery`/`assertOptionalPort`/`toByteRange`）+ 订阅 `coreRuntime.onCaptureEvents` 广播 `capture:events`。
