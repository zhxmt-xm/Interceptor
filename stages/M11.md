## 实施

### 平台适配

- `main/system-proxy/windows-helper.cs` 使用 WinINet per-connection API 读写 flags、Proxy Server、Bypass、PAC URL 和 Auto Detect；写后广播 settings changed/refresh。参数逐项 Base64 编码并经 `execFile` 数组传递，不经 shell。
- `main/system-proxy/macos-helper.swift` 使用 `SCPreferencesCreateWithAuthorization`、当前 `SCNetworkSet` 和每个活动 `SCNetworkService` 的 Proxies protocol；先验证完整 service 集合，再统一 set/commit/apply，避免部分服务落盘。Swift helper 通过 `xcrun swiftc` 构建。
- Windows/macOS TypeScript service 都保存 original/owned 精确快照。任一当前字段或任一 macOS service 不再等于 owned 时，restore/repair 只返回 `externally-modified`，不会写系统设置。
- `build:native` 按宿主平台构建 helper；Forge 在 Windows/macOS 把 `dist/system-proxy` 放进 `resources/system-proxy`。当前 Windows 包含 `wininet-proxy-helper.exe`。

### 崩溃恢复

- `SystemProxyJournal` 在 helper 写入前以 `preparing` 原子落盘 original/owned，完整临时文件 `fsync` 后 rename；写后回读验证成功再标记 `owned`。journal 限制为普通文件和 1 MiB，JSON envelope 有版本、平台与 phase 校验。
- 新进程启动时：`current == owned` 才恢复 original；`current == original` 只清理 journal；其他值视为外部修改并保留冲突，不覆盖用户设置。
- Core 从 `running` 进入 `unresponsive/restarting` 时 Main 串行触发同一 guarded repair。关闭 Capture 或退出应用仍先恢复，再停止 listener；恢复 I/O 失败时保留 listener。
- `repairSystemProxy` 是 Renderer 唯一 emergency repair 意图：先 guarded repair，再尽力停止 Core listener。Main/Core/Renderer 日志不记录 snapshot 内容。

### 首次运行与 Settings

- first-run 以 `interceptor.first-run=completed` 作为 profile 完成标记。Welcome 明确默认不捕获；Proxy 步骤选择自动路由或手工 `127.0.0.1:8888`；CA 步骤真实生成、安装并验证；最终按钮先 `startCapture(8888)`，listener 成功后才启用系统代理。
- 系统代理启用失败时，向导先 guarded restore，再停止刚启动的 listener，避免遗留指向关闭端口的设置。
- Proxy Settings 展示真实 listener、owned/external/ownership-lost/unavailable、当前 proxy/bypass/PAC/Auto Detect、操作授权结果与 journal 保护；Emergency repair 必须二次确认。
- `design/app` 是视觉真源，新增 first-run 四步及 Proxy/repair 状态；业务 Renderer 无 parity fixture 或测试 setter。

### 后续简化（2026-07-18）

- 删除 `FirstRunWizard`、`interceptor.first-run` 启动分支及其设计/截图资产；应用默认进入 Capture，不再用首次运行流程阻断正常抓包。
- Capture 首次挂载等待 Core ready 后启动固定 8888 loopback listener，并在支持的平台尽力启用系统代理；Windows/macOS guarded ownership、startup journal、外部修改保护和 emergency repair 不变。
- HTTPS 默认不解密，CA 生成/安装从启动流程移到 Capture Tunnel 面板的用户触发 setup；系统代理接管与 Root CA 授权不再绑定为一个流程。
- Stop Recording 继续先 guarded restore 系统代理，再真停止 Mockttp listener；M14 起保留已有记录，只有 Clear 删除。恢复失败不会静默覆盖外部代理设置。

## 决策与限制

- 系统代理由 Electron Main 独占；Proxy Core 不直接访问 OS 设置，Renderer 只使用四项意图 API。
- Windows 只管理当前用户 WinINet；WinHTTP 仍是独立、未实现的管理员操作。
- macOS helper 源码、构建与多服务状态机已完成；当前验收宿主为 Windows，Swift 编译、真实 Authorization、macOS package 和系统设置 round-trip 必须在 M12 的真实 macOS/Xcode 环境完成。
- First-run 固定请求 8888，确保展示的手工地址与 listener 一致；普通 Capture 开关仍允许 Core 选择可用端口。
