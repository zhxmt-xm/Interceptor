## T11.1 Windows 系统代理（已完成）

### 实施

- **模块边界**：实现全部收拢在 `apps/desktop/src/main/system-proxy/`：`windows-helper.cs`、`build-windows-helper.mjs`、`windows-system-proxy-service.ts` 与 tests 直接位于该模块，不保留独立 `native/` 或仓库根构建脚本。Main、Preload、Forge 只保留组合、窄契约和资源声明。
- **WinINet helper**：零第三方依赖的 C# helper 使用 Windows `InternetQueryOptionW` / `InternetSetOptionW` 与 `INTERNET_OPTION_PER_CONNECTION_OPTION`，读取/写入 flags、Proxy Server、Bypass List、PAC URL 和 Auto Detect；写后调用 `INTERNET_OPTION_SETTINGS_CHANGED` 与 `INTERNET_OPTION_REFRESH`。字符串参数经 Base64 逐参数传递，不经 shell。
- **构建与打包**：Windows 使用系统自带 .NET Framework `csc.exe` 编译到 `apps/desktop/dist/system-proxy/`；Desktop `start/package` 自动执行 `build:native`；Forge 把整个目录放入 `resources/system-proxy/`。非 Windows 构建显式跳过 helper。
- **安全所有权**：`WindowsSystemProxyService.enable` 先完整读取原值，再写 loopback-only `http/https` proxy、关闭当前 PAC/Auto Detect 并回读验证；内存中分别保存 original/owned 快照。`restore` 只有在当前五项值仍精确等于 owned 快照时才写回 original；任一外部修改都返回 `externally-modified`，只读一次且零写入。
- **生命周期**：Renderer 仅有 `getSystemProxyStatus` / `enableSystemProxy` / `restoreSystemProxy` 三项意图 API。enable 从真实 Core `proxy.status` 获取 listener，非 listening/非 loopback 均拒绝。停止 Capture 和退出前先 guarded restore；恢复 I/O 失败时取消退出并保持 Core listener 可用，避免遗留指向已关闭端口的代理；外部修改则不覆盖并允许退出。

### 验证

- `npm run typecheck`：Desktop / Proxy Core / Core Protocol 全通过。
- `npm run test:unit`：Desktop 53、Proxy Core 187、Core Protocol 19 全通过；新增 6 项覆盖 snapshot、写入参数、精确恢复、外部修改零写入、二次 enable ownership conflict、非法 helper 输出与 unsupported 平台。
- 真实 helper：`get` 返回当前五项 WinINet 设置；用完全相同值执行 `set` 后逐字段比较完全一致，验证原生写路径与变更通知且未改变本机代理配置。
