## 实施记录

### 关键决策

- **代理引擎采用 Mockttp（`getLocal()`）**，不自研原生代理。Mockttp 是 HTTP Toolkit 同源库，直接支撑 M5 HTTPS MITM 与 M6 HTTP/2，早引入早统一。已实测它在 Electron 43（Node 24）UtilityProcess 运行时可用（`require` + 起代理转发 200），且 `npm audit --omit=dev` 0 漏洞。
- **打包方案：esbuild 只打包自己代码，`mockttp` 标 `--external`，用 `@vercel/nft` 追踪 `entry.cjs` 运行时依赖闭包并按 node_modules 结构拷进 `dist/proxy-core/node_modules/`；Forge `extraResource` 递归随包发。** 原因：Mockttp 依赖含 WASM（`brotli-wasm` 的 `.wasm`）与原生插件（`tls-impersonate` 的 `.node` prebuilds），二进制无法内联进单文件，必须以真实文件随包发、按相对路径/dlopen 加载。
- **nft 两处坑已修**：① nft 静态追踪抓不到 node-gyp-build 运行时加载的 `.node`，故在 nft 后对每个随包依赖补拷 `prebuilds/` 与 `build/Release/*.node`（tls-impersonate 5 平台 prebuilds 全带）；② 拷贝时必须从**第一个** `node_modules` 段起保留嵌套结构，否则会把嵌套的 `finalhandler/node_modules/statuses@1.5.0` 拍平覆盖顶层 `statuses@2.0.2`，导致 `http-errors` 加载崩溃（`statuses.message` undefined）。
- CONNECT 在 M3 只做不解密的字节直通（HTTPS 内容对代理不可见），解密在 M5 引入。
- 代理默认不自动监听，由 `proxy.start` 命令显式开启（符合“默认不捕获”）。

- `apps/proxy-core/src/proxy-core/proxy/tests/`：`proxy-service.test.ts`（会话/状态、转发+规范 Exchange 捕获）、`proxy-storage.integration.test.ts`（proxy + 真实 Storage Worker + 真实源站端到端）。
- 打包：`apps/proxy-core/package.json`（`mockttp` 依赖 + esbuild `--external:mockttp` + build 末尾跑 ship 脚本）、`scripts/ship-core-deps.mjs`（nft 依赖闭包 + 原生资源补拷 + mockttp 可解析自检）。
- 协议：`packages/core-protocol/src/{messages,validation}.ts` 新增 `proxy.start`/`proxy.stop`/`proxy.status` 命令与 `proxy.status` 结果及校验。

### T3.4 增量事件与背压

- **数据流**：`ProxyService.onCaptureEvent`（Exchange 完成/更新）→ `CaptureEventQueue`（`apps/proxy-core/src/proxy-core/proxy/capture-event-queue.ts`，有界、按 id 合并、保留终态、分配单调 sequence）→ `CoreApplication.flushCaptureEvents` 按窗口背压排空（`MAX_INFLIGHT_EVENT_BATCHES=8`、`EVENT_DRAIN_BATCH=200`、`EVENT_FLUSH_INTERVAL_MS=50`）→ `CoreRpcServer.sendEventBatch` 发 `event-batch` → Main `CoreRpcClient` 收批回 `event-ack` 并触发回调 → `CoreRuntime.onCaptureEvents` → Main 经 `capture:events` 广播 Renderer。
- **协议**：`packages/core-protocol/src/messages.ts` 定义 `CaptureExchangeSummary`（分页查询与实时事件共用的单行摘要，含 `secure`/`durationMs`）、`CaptureExchangeEvent`、`CoreEventBatch`（`event-batch`）、`CoreEventAck`（`event-ack`），`MAX_EVENT_BATCH_SIZE=500`；`validation.ts` 全量校验。`sessions.query` 结果统一返回 `items: CaptureExchangeSummary[]`（不再是 id 列表），使查询与实时事件共用同一行结构。
- **代码位置**：`capture-event-queue.ts`、`core-application.ts`（flush/背压/`onEventAck`）、`core-rpc-server.ts`（`sendEventBatch`/`hasActiveConnection`/`onEventAck`）、`core-rpc-client.ts`（`onCaptureEvents`/`handleEventBatch`+回 ack）、`core-runtime.ts`（`onCaptureEvents` 委派）。
