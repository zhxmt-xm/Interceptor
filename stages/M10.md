## 进入条件与记录规则

- 所有导入按不可信输入处理，限制路径、尺寸、数量和压缩比。
- Diagnostics 导出默认脱敏，不包含 Body、Authorization、Cookie、Token、CA 私钥或敏感 URL Query。
- Main/Renderer 日志汇入 Diagnostics 时复用 Core 的脱敏规则与有界策略；日志必须标注 process 来源，跨进程可按 trace/请求关联；Renderer 侧只经既有窄 IPC 通道上报，不放宽 Preload 面。
- 开始后按 Server/Contract/Client 分别记录进度，并记录格式版本、安全测试、兼容性、截图验证和剩余工作。

## T10.1 HAR 1.2 导入/导出（已完成）

### 实施

- **Core HAR 门面**：`proxy-core/har/entry.ts` 的 `HarService` 直接作为模块入口，组合 `HarJobManager`、`HarDocumentParser`、`interfaces/index.ts` 与 `utils/index.ts`。导出按 Storage keyset 页枚举 detail，正文只在 Core 从 Blob 分块读取，HAR entry 逐条写同目录临时文件后替换目标；导入先完成不可信 JSON/schema/数量/正文校验，再建立 `har-import` Session、分批写 Blob/Exchange，失败或取消按新 Session 回滚并 GC 孤立 Blob。
- **HAR 映射**：导出标准 `log.version=1.2`、creator、request/response/header/query/cookie 空数组/content/timings；文本正文直接写 text，二进制用 base64（request 使用 `_encoding` 扩展，response 使用标准 `encoding`）。导入映射 HTTP/1.1/H2/H3、状态、header、MIME、时序与双向正文；捕获到的 `<script>` 只作为 inert 字节存储，代码中不存在 eval、DOM 注入、插件或脚本执行路径。
- **格式损失**：HAR 无法表达 HTTP/2 pseudo-header/trailer、WebSocket message、TLS detail 与 rule history；Core 完成结果与 UI 都显示警告。Native archive 显示 disabled，留 T10.2。
- **异步任务契约**：Core protocol 新增 `har.export.start`、`har.import.start`、`transfer.job.get/cancel` 与 `TransferJobSnapshot`；任务有界保留 100 项，使用专属 AbortController，公开快照只含 basename/进度/状态/警告，不返回绝对路径。Main 通过 Electron `showSaveDialog/showOpenDialog` 产生真实路径，Renderer 只提交 scope/redaction 并轮询 job，永不获得通用文件系统 API。
- **Renderer**：Capture Topbar 的 More 按钮打开 `HarTransferDialog`；支持 all/current filter/selected scope（current filter 会把 H1/H2/WS protocol group 一并下推）、Authorization/Cookie 遮罩、strip bodies、Import/Export、进度、取消、失败和警告。All traffic 数量来自 `storage.status`，分页 filter 不冒充已知总数。导入完成重新拉取 Capture 首页。业务 Renderer 无 fixture/DEV setter；visual parity 通过 fake Preload + 正常 UI 点击建立状态。
- **输入上限**：HAR 文件 256 MiB、100,000 entries、每 entry 1,000 headers、单 header value 8 KiB、URL 16 KiB、单 body 64 MiB；仅接受 `http/https/ws/wss` URL；base64 使用严格语法校验。Main/Core 两层 command 校验 scope、selected ID、filter、redaction、path 与 job ID。
- **Core 模块结构统一**：按仓库约定同步整理 composer/connection/diagnostics/grpc/har/proxy/rules/storage：根 Service/Engine 直接位于 `entry.ts`，显式类型集中 `interfaces/index.ts`，无状态函数集中 `utils/index.ts`，其余文件使用模块前缀且一文件一个 class；host/worker 子模块入口为 `entry.ts`、其余文件保持 `host-*`/`worker-*`。esbuild 与运行时 resolver 已同步输出 `storage/worker/entry.cjs`、`diagnostics/worker/entry.cjs`。

### 安全与兼容性决策

- 导入只用 `JSON.parse` 与结构化字段读取，未知扩展字段忽略；不加载远程资源、不渲染捕获 HTML、不执行脚本。
- 导出默认开启 Authorization/Proxy-Authorization 与 Cookie/Set-Cookie 遮罩；正文移除为显式可选项。T10.3 仍需完成全局隐私设置、URL query/token 遮罩、默认录制安全与未脱敏导出确认，不能把本任务视为 T10.3 完成。
- 文件路径只存在于 Main→Core 内部 typed command，Preload/Renderer 与公开 job snapshot 均不含路径。Diagnostics 只记录 command/action 安全摘要，不记录 payload。
