## 实现记录

### T9.1 WebSocket 捕获（已完成）

- `ProxyService` 注册独立 WebSocket 规则，订阅 `websocket-request` / `websocket-accepted` 捕获 HTTP/1.1 Upgrade 握手，并将成功连接作为 `101 Switching Protocols` Exchange 落库；拒绝和异常中止路径也会完成/清理 pending 状态。T9.2 后规则 step 由 `WebSocketBridge` 接管消息转发，以提供真正的转发前断点。
- 订阅 `websocket-message-received` / `websocket-message-sent`，映射为 `client-to-server` / `server-to-client` 与 opcode 1(text)/2(binary)。每个 `streamId` 使用独立 Promise 链，保证先等待握手 Exchange 落库，再按 Mockttp 事件顺序持久化消息。
- payload 复用 Blob Store 内容寻址写入；`StorageWorker` 新增 `append-websocket-frames` 请求，在单事务内插入 `body_ref` 与 `websocket_frame`，同一 Exchange 的 `seq` 从现有最大值继续递增。
- message 的单调高精度时间通过 `startTime + (eventTimestamp - startTimestamp)` 转换为 Unix 毫秒；正文媒体类型按 text/binary 标记，正文失败仍保留 payload size 与 skipped/truncated 元数据。
- **可观测性边界**：Mockttp 4.5 暴露的是重组、解压后的应用 Message，不暴露 continuation、ping/pong、mask 位等原始 frame；`websocket-close` 不提供方向，因此当前只记结构化关闭诊断，不伪造 opcode 8 子记录。HTTP/2 Extended CONNECT 不在 MVP 范围。

**验证**：Proxy Core typecheck 通过；`worker-store.test.ts` 验证跨批次 seq + payload body_ref；真实 WebSocket echo 测试验证 HTTP absolute-form Upgrade、101 Exchange、双向 text/binary 有序消息与 Blob 引用；重建 Core 后真实 Storage Worker 测试验证 host→worker 请求和 referenced hash。聚焦结果 2 files / 8 tests 通过。

### T9.2 WebSocket UI 与消息断点（已完成）

**Server / 数据面**

- `proxy/websocket-bridge.ts` 使用 Mockttp 本地 `addWebSocketRule` 自定义 step：Mockttp 继续拥有 listener、HTTP Upgrade 预处理和 accepted/message/close 观测事件，bridge 用直接依赖 `ws` 连接上游并接管双向应用消息转发；不重写 HTTP/TLS listener。
- client→server 与 server→client 各自使用 Promise tail 串行，保证同方向消息顺序；每条 text/binary message 在 `send()` 前 await 拦截决策。开启消息断点后进入现有 `BreakpointQueue`，支持 continue、edited body、drop 和 30s 自动继续；binary 编辑采用十六进制文本并严格校验。
- WebSocket 消息断点使用独立开关（默认关闭），不混用 HTTP Rule 的全局 break-on-match；`websocket.breakpoint.configure` 原子切换。bridge 透传 close/ping/pong，错误时确定性 terminate 两端。
- WebSocket Exchange 在 101 后保持 `request-complete`（列表显示 open），clean close 时通过 `StorageService.updateExchange` 更新为 completed 并发送 `exchange-updated`；scheme `wss` 正确标记 secure。
- `ws` 声明为 Proxy Core 直接依赖，并与 Mockttp 一样通过 esbuild `--external:ws` 保留运行时 require，由 `ship-core-deps.mjs` 随 packaged node_modules 发布。内联 `ws` 会让首代 Electron UtilityProcess 在 entry 顶层前阻塞（bundle 约 283KB、Core 停在 starting）；external 后 entry 回落约 159KB，首代 Core 正常 ready/heartbeat。临时启动探针只用于定位，已全部删除。

**Storage / Contract / IPC**

- `CaptureStore.queryWebSocketFrames` 按单 Exchange `seq ASC` 做 opaque keyset 分页（limit+1 判 hasMore），支持方向过滤；只返回方向/opcode/time/size 与 `CaptureBodyRef`，不读取 payload 字节；到尾仍返回 tail cursor 供 2s 增量轮询，不重扫历史。
- `websocket.frames` command/result 资源上限与完整 runtime validation 已接入 Core protocol、`CoreResultForCommand`、Main RPC result mapping 和 `CoreApplication`；payload 继续复用 `body.read-range`，大正文不进入 Main 或 Renderer 全局状态。
- Main `toWebSocketFrameQuery` 二次校验 exchange id、cursor、limit≤500 和 direction；Preload 只暴露 `queryWebSocketFrames` / `setWebSocketBreakpointsEnabled` 两项意图 API。Packaged smoke API keys 已同步。
- Breakpoint contract 扩展 `phase:'websocket'`，快照带 direction/opcode/bodyFormat(text|hex)/body；现有 `breakpoint.list/resolve` 路径复用，不新增通用命令。

**Client / Design**

- Capture Inspector 对 protocol=ws 动态显示 `Headers / Messages / Timing / TLS`，默认进入 Messages，101 显示 Connected；普通 HTTP 标签不变。
- `WebSocketMessages` 使用 TanStack Virtual 固定 38px 消息行 + 可测量内联 payload 展开；All/Sent/Received 方向过滤、滚动近底分页、tail cursor 2s 增量轮询。可见行按需只读前 160B 生成 text/hex 摘要，选中行用紧凑 `BodyView` 读取最多 256KiB payload。
- “Pause on message” 接真实 Core 开关；命中后进入 Breakpoints workspace。PausedQueue 显示方向与 Text/Binary，BreakpointEditor 只编辑 payload（text/hex），Drop/Continue/Execute edited 复用原操作。
- `design/app` 新增 WebSocket scene 与 light/dark `inspector-websocket.png` 基线。

**限制**

- 持久化与 UI 展示的是 Mockttp/`ws` 重组、解压后的应用 Message，不是原始 frame；continuation、mask、permessage-deflate wire bytes 不展示。Ping/pong 由 bridge 透传但不伪造为方向不明的应用消息记录。
- HTTP/2 Extended CONNECT 仍不在 MVP；T9.1/T9.2 目标是 HTTP/1.1 Upgrade。
