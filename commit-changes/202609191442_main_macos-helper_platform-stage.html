将 macOS 系统代理和公开证书操作接入随 App 交付的常驻 helper，分离开发与生产准入；平台原生差异集中到 Main 和 E2E driver，保留两端共同的业务流程。

续作加入接管前上游配置、按协议转发与前台证书信任入口。本次删除无效的自动 trust、临时授权规则和恢复实现，直接由前台 helper 请求正常系统确认；不改变 SIP、共享认证规则或 Windows 原生操作。平台职责、profile 外状态、业务隔离与实际差距分别说明。

Main

位置改前改后原因与影响
macos/trust-store/、helper-client.ts 与对应原生测试常驻 helper 先临时修改 trust 授权规则，恢复后再决定是否转前台确认。删除自动授权及规则恢复组件；trust/untrust 直接调用普通用户前台 helper，不保留后台尝试、回退或旧系统兼容分支。本机 root 也被系统拒绝，不能靠临时规则省去确认。保留正常系统授权、明确取消回滚和证书结果不确定时的 CA 保护，不删除可用的信任功能。
native-service.swift、协议类型、构建输入与 native-installation.swift后台协议包含 trust/untrust，启动及卸载依赖授权规则恢复记录。后台只保留状态、代理及公开 CA 存取；删除规则 journal、恢复入口、专用错误和专用测试，保留前台 CLI。能力列表对应实际可执行操作；缩小常驻 root 服务职责。组件部署鉴权与系统代理恢复逻辑保持，私钥仍不进入 helper。
src/main/platform-capabilities/、main.ts 与 Core 调用方系统代理、trust、AppContainer 和 client-app 原生入口分散在 Main 多个目录。统一 PlatformCapabilitiesService 入口、DTO 和错误类型，Windows/macOS 实现分别归平台目录，更新原生路径调用方。Main 继续负责业务编排、代理 FIFO 和退出恢复；Core 缓存与事件不搬迁。Windows 原生命令、数据契约和产物名称保留。
macos/installation/ 与 Main 启动macOS 代理依赖一次性授权工具，不同进程需要重新申请网络写权限。首次启动核准随包 helper，部署 root 保护的组件、配置和 launchd；后续核对身份并复用，失败按事务恢复已有组件。App 留在原位置，不另装完整 App .pkg，不下载独立 helper。只有缺失或身份不匹配才请求部署，未知或损坏状态不覆盖。
macos/system-proxy/native-service*.swift、helper-client.ts缺少跨启动复用的特权服务和独立开发准入。同一服务提供 service.sock 与 development.sock；生产核验准确 App 路径/CDHash、完整资源和运行时，开发信任核准的本机 UID。Forge、HMR、rs 和业务 E2E 无需按每次源码构建重新核准。开发授权允许该 UID 的本地程序使用固定能力，不宣称隔离同用户恶意代码；请求不能降级生产鉴权。
macos/system-proxy/ 与 macos/trust-store/代理写入依赖一次性命令；CA 存在与实际信任混淆，信任取消可能留下新导入证书。代理采用完整 expected/replacement 快照条件写入；helper 只接受固定操作、公开 DER 和指纹。Main 验证实际信任，取消时撤回本次新导入 CA，已有 CA 不删除。保留 ownership/journal 恢复语义，避免误删已有证书；admin trust 仍由登录用户处理独立系统授权。helper 不接收任意 shell、私钥或证书文件路径。
macos/trust-store/native-certificates.swift、helper-client.tsMain 直接启动 security 执行 trust/untrust。由已部署 helper 的固定前台入口执行 Security API、系统确认和回读，Main 保留安装顺序与失败回滚。权限操作归原生组件；不把安装 helper 等同于永久批准证书信任，不取消 macOS 要求的独立确认。
macos/system-proxy/upstream.ts、entry.ts、journal.ts只保存各 network service 的恢复快照，Core 未接续 macOS 原上游。接管前读取系统生效代理，分别保存 HTTP/HTTPS、PAC、SOCKS 与绕过规则；journal 只写 original/owned/effectiveProxies，重启复用原上游。流量可以继续经过 ClashX 等外部代理；地址规范化后排除本机 listener 自环，不合并或覆盖原 network service 配置，不保留版本迁移代码。

Core

位置改前改后原因与影响
core-protocol/messages.ts、proxy/entry.ts 与 proxy/utils/上游只有一个 URL，不能表达 macOS 两种协议不同的目标和原生绕过规则。增加按协议的当前配置，macOS 通过 Mockttp 公开规则接口选择目标；Windows 保留原单规则和单上游契约。保持流式头部处理和监听器生命周期；不修改 Mockttp patch，不把未配置某个协议误当作另一个协议的上游。
proxy/internal/websocket-bridge.ts 与 Main 上游探活WebSocket 只处理单一 HTTP/HTTPS CONNECT 上游。macOS 按协议配置使用既有 HTTP/SOCKS/PAC agent；单上游路径保持原行为。只有一个明确上游目标时才提供整体探活结果。避免 macOS 新能力改变 Windows 路径，也避免一个协议的上游失败导致全部流量降为直连。

工程与文档

位置改前改后原因与影响
forge.config.ts、原生 build 脚本与 entitlements原生源码分散，重复构建/打包可能改变同一 helper 的签名身份。统一 helper identifier、Hardened Runtime 与空 entitlements，按原生输入和产物 hash 复用构建；本地 ad-hoc App 仅保留必要运行权限。开发与随包 helper 使用同一身份，源码未变不替换组件；Developer ID、Fuses/CSP 和 Windows 原有门禁保留，用户开发命令仍运行 Forge。
tests/e2e-workflow-tests/fixtures/ 与共同 workflow 调用点启动、窗口、文件 Dialog、journal 和恢复观察主要按 Windows 运行方式组织。macOS 通过真实未打包 Electron/CDP 复用开发 helper，原生 Save/Open/Cancel 使用真实键鼠；平台 driver 负责窗口、路径、超时及恢复观察，workflow 共用原业务输入和断言。Windows 保留原 _electron.launch 和原生 Dialog driver。macOS 先确认代理恢复再终止 App；私有文件日志避免 runner 退出产生 EPIPE，crash 后立即保存初代证据。
Settings fixture、宿主 guard 与 tests/packaged-smoke/startup.spec.tsAuto 点击完成不代表设置已保存，原生窗口暴露与截图准备存在竞态。等待公开的 Auto 持久化状态；按精确 Main 代际等待 macOS 原生窗口，调整实际窗口尺寸；guard 比较完整代理及 admin trust。不注入 Store、不改写原生窗口返回值、不增加产品测试入口；Windows 原有窗口矩阵和系统恢复路径保留。
Main 模块 README、开发/平台说明、功能与 E2E 规格、Handover文档按旧目录和一次性授权入口说明运行方式。同步首次启动部署、双入口权限、平台分派、真实流程和退出恢复约定。明确开发与生产的信任边界，保持代码路径和操作说明一致；独立 package 不提前接入。
macOS 证书、ClashX workflow 与平台 fixture证书窗口、信任查询和 journal 格式部分直接按 Windows 处理；证书流程断言自动尝试/回退日志，撤销仅等待15秒。Windows 委托原驱动；macOS 独立处理原生窗口、信任查询和当前 journal。证书流程要求直接前台授权、没有自动尝试日志，完整授权规则保持不变；仅macOS专项撤销等待改为120秒。为真实系统确认保留时间，复用产品 UI、Main 和 helper，不注入 Store 或授信结果；不改变 Windows 的业务操作、超时和原生驱动。
Handover、平台模块说明与进程文档同一进度表混合模块迁移、权限执行者和存储生命周期，无法区分当前与目标。分别列出执行者、profile 外复用状态、profile 内业务隔离和当前差距：macOS journal 仍在 profile，CA 材料两端均未独立存放。OS 代理设置不在 profile，不代表恢复文件也已共享；helper 复用不代表 CA 私钥或系统 trust 免确认。只澄清归属，不夹带 journal/CA 迁移。
architecture/HANDOVER.md 与 Settings 文档任务正文混入大量按日期排列的排障经过。Handover 保留短状态清单、角色、结果表和恢复命令，原验证记录归入所属功能文档。减少重复说明；保留原始证据与平台边界，不改写历史失败。
