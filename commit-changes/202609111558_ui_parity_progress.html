UI 一致性改动

Capture、Settings和Shell的布局、控件状态及parity场景修正。

UI 改动

位置改前改后与影响
Capture · CaptureStatusbar三列缺少设计的16px grid gap，端点列宽多16px。补齐gap，列宽差归零；文字、状态、30px栏高与交互不变。
Capture · RequestList / RequestRow列轨道、12px间距、18px内边距及窄宽度规则与设计不一致，Path宽差34px。按设计使用10px间距、14px内边距和相同列轨道；500/380px按序隐藏列。文字自然行高，保留34px表头、52px数据行与滚动条补偿。
Capture · 清空筛选按钮禁用opacity为0.55，启用色为text-2。局部还原为0.35与text-3；保留hover、筛选与清空记录的职责区别。修正误测wrapper和无显示作用字号的parity目标。
Messages · FramePayload标题缺失翻译键导致“已发送 capture.text”。复用FrameRow已有的Text翻译；消息正文、方向、Copy及二进制标题不变。
Messages · WebSocketBreakpointControl默认颜色/边框不同；启用后hover被普通IconButton样式覆盖，黄色消失。30px按钮、1px透明边框、主文字色；默认hover取Ant Button token，启用hover保留黄色。共享IconButton的可选CSS变量保留原默认值。
gRPC · GrpcMessages.message消息与压缩标签文字盒比设计少1.1px。局部自然行高消除差异，38px数据行、字体、字号、选择与Copy保持。

工程与文档

  • Settings Proxy：通过正常UI展开侧栏，Listener地址限定到Address行，消除160px状态误报与重复文字错配；明暗共用13项目标。
  • Certificates：明确展开侧栏并打开Certificates，改用已有framed截图路径，恢复像素检查；两个约1px差异仍保留。
  • 旧Shell Settings/Diagnostics：补正常导航、标题DOM Range测量和正确framed路径；Rules/Composer配置结果不变。
  • gRPC与WebSocket场景明确collapsed/open状态，补深色和实际图标目标；补齐既有场景缺失的4张PNG，已有设计和旧基准内容不变。
  • Clear场景适应系统背景流量，不再假定全局只有一条请求；清空筛选和清空记录仍是不同操作。
