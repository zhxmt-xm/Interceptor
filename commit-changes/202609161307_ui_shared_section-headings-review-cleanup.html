UI

位置改前改后原因与影响
共享 SectionHeader；Capture、Rules、Composer、Diagnostics 等调用页面默认最小高度 24px，普通标题较矮；带状态标签和模式控件的标题被内容撑高。公共默认 min-height: 36px，保持 Flex 垂直居中。较高内容可继续自然撑开，折叠时仍保留同一下限。统一标题行与左侧标记的基础尺寸，不缩小控件，不改字号、内边距、正文或折叠行为。
Capture / HTTP 与 WebSocket 的 Replacement 标题各自保留 30px 的局部下限，覆盖公共标题规则。删除局部高度覆盖，统一继承公共默认；Off / Text / File 和原有折叠入口不变。同一组件不再因调用位置不同而使用另一套最小高度。
design-vite 的 CollapsibleSection、普通 .sh 和 PayloadEditor普通分组标题仍为 24px；Text 判定会先 trim 输入。公共标题同步 36px，更新对应设计图；空格输入按实际内容显示 Using text，严格空串仍显示 Using original。设计与产品公共样式及普通 HTTP 空 Text 语义一致，不引入 Empty body 标签或修改 App 的正文处理。
Capture / Timing 的正文阶段标签；15 语言资源Storage 清理误删仍被 Timing 使用的 settings.responseBodies，标签退回缺省文字，右侧数值位置随之变化。原样恢复已有翻译值，Timing 恢复原有标签；既有 i18n 必需键检查覆盖该调用。补回实际仍在使用的资源，不恢复 Storage 已移除的统计行，也不改变 Timing 的布局或数据。
