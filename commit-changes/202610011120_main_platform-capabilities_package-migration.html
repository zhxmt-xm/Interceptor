平台能力迁入内部 package

提交改动说明 · Handover 第 11 项 · 2026-10-01 11:20（本地时间）

把已聚合的平台实现迁入 @interceptor/platform-capabilities，解除对 Desktop Main 类型的反向依赖；不改变原生业务、系统授权或用户操作。

Main

位置：平台入口与 DesktopApplication

改前
系统代理、证书、AppContainer、图标及 helper 位于 apps/desktop/src/main/platform-capabilities，直接依赖 CoreRuntime、MainDiagnostics 和 Desktop DTO。
改后
实现迁入 packages/platform-capabilities/src，旧实现删除。Main 注入 typed requestCore、getCoreProcessState、DiagnosticsRecorder、safeStorage、资源路径和通知。
原因与影响
平台包不加载 Electron，不反向导入 App。各模块继续独占操作状态，冲突立即拒绝；证书材料、系统信任、上游同步和退出恢复仍各由原 owner 执行，不恢复操作队列。

Core

位置：client-app 与共享类型

改前
Core 的 client-app utils 同时持有原生查询、TSV 解析和 loopback 判断；Main 自己定义平台公开 DTO。
改后
原生查询和应用身份解析来自 package 的独立 client-app 入口；Core 保留缓存、失败退避、Capture 关联和事件交付。平台 DTO 在 package 定义，Desktop API 只作 type 导出；进程状态类型和两进程共用的诊断契约归 core-protocol。
原因与影响
Core 不因此加载证书或系统代理编排。Renderer 的 Preload 参数和返回值形状保持，私钥、应用路径及原生快照的隐私边界不变；不补 macOS 尚未实现的应用归属。

工程与文档

位置：原生构建、Forge、测试与 package 文档

改前
内部 package 只有骨架；原生构建和 entitlements 归 Desktop，开发资源读取 Desktop dist。
改后
原生源码、所属测试和空 entitlements 同步迁入 package，产物写入 package dist。Desktop 调用 package 的 build:native；Forge 与 E2E 读取新开发路径，最终 App 仍使用原同名 resources 目录。
原因与影响
原生源码和 helper 文件名保持。Main 类组合回归留在 Desktop，其他模块回归随实现迁移；更新 workspace 依赖、lockfile、架构与开发说明。package 保持 private，不增加独立安装器、下载或更新机制。

本项没有修改 Renderer 布局、样式或视觉状态，不附无关 UI 对比。运行结果与剩余验收统一记录在 Handover。
