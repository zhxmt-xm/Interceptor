Capture筛选计数统一为request数量

2026-10-04 11:32

分组标题不再显示筛选项或类别数量，改为该组覆盖的request数量。一个request命中多条规则时，规则组只计一次；零值Pending入口不增加总数。

UI

Capture左侧筛选分组的计数徽标

位置：apps/desktop/src/renderer/features/capture/ 下的utils.ts、interfaces.ts及CaptureFilterPanel/组件。

改前：组头直接显示options.length，与选项旁的request数量使用不同口径；零条Pending也会增加组头数字。

改后：同一次facet遍历同时生成选项与requestCount。组头读取request覆盖数量，All和单个选项仍使用原来的request数量。

相关行为约束同步到Capture unit测试与现有facet-stable-ordering、clear-facets真实workflow，覆盖多规则去重、request总数和全部组头清空。

原因与影响：避免把“3条request、2种方法”显示成组头2。Rule组按request计数，不把多个规则的命中次数直接相加；Clear后全部组头归零。

保留筛选行为与布局

改前：Pending固定存在，facet按首次出现或协议/状态语义排序，组内OR、组间AND。

改后：上述行为不变；保留Pending 0、All、折叠和“显示更多”。新增All计数的公共automation ID，只暴露原本显示的数量，不增加业务入口。

原因与影响：修改的是计数单位，不改变筛选结果、录制行为、样式、间距、字体或主题。

工程与文档

位置：Capture功能文档、对应workflow规格、Renderer automation契约与Handover。

改前：主要约束选项顺序、单项数量与Method清空，没有明确组头必须使用request单位。

改后：补充分组request数量、零记录、Pending迁移、多规则去重和完整清空约束；真实workflow通过公开计数控件比较Method与All，并核对全部组头归零。

原因与影响：将计数含义写入功能契约与现有业务验收，不修改Core、IPC、第三方补丁或设计基准。
