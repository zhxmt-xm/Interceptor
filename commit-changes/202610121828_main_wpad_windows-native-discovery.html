Main · Windows 平台能力

Windows WPAD 原生发现接入

改动说明 · 2026-10-12 18:28（本地时间）

让 Windows 的显式 WPAD 和 System 仅 Auto Detect 配置真正执行原生发现，再由既有 Core PAC 引擎选路。对外调用不变，macOS 功能代码不动。

Main / Windows 平台能力

原生 helper 增加只读发现

位置packages\platform-capabilities\src\system-proxy\windows\helper.cs

改前只有 get / set，不能返回 Windows 当前网络的 WPAD PAC URL。

改后同一个 helper 增加 discover-wpad，调用 WinHttpDetectAutoProxyConfigUrl。DHCP 优先、DNS 后备，只返回 URL 或 Win32 错误码；不下载或执行 PAC，也不写系统代理。

影响复用 Windows 原生策略，不另写 DHCP/DNS 客户端，不新增安装组件或 npm 依赖。

Windows 内部实现，对外 API 保持统一

位置system-proxy\entry.ts、windows\entry.ts、windows\discover-wpad.ts

改前共用发现入口只连接 macOS helper，Windows 选择 WPAD 会报告平台不支持。

改后共用入口只增加 Windows 分派，由 WindowsSystemProxyService 执行限时发现；既有 getUpstreamSettings()、applyUpstreamSettings() 和通知链路不变。

影响macOS 原发现调用、原生协议、选路及恢复逻辑原样保留；Core 继续负责 PAC 下载、编译及逐请求选路。

System Auto Detect 不再被误判为 Direct

位置windows\system-proxy-upstream.ts、windows\helper.cs

改前仅 Auto Detect 没有现成 PAC URL，转换结果为无上游。

改后在读取的原配置只有 Auto Detect 时先发现，再生成临时 pac+<url> 运行配置；保留原 bypass 和显式代理/PAC 优先级。读取使用 INTERNET_PER_CONN_FLAGS_UI，写入与恢复仍使用 INTERNET_PER_CONN_FLAGS。

影响不把发现结果写回 WinINet 或 journal，不保存过期网络 URL，不把已接管的 8888 当作原上游。

明确失败并保留旧路线

位置windows\discover-wpad.ts及所属 Windows 测试

改前Windows 没有原生发现错误分类与发现进程期限。

改后发现调用限制为 30 秒、64 KiB 输出；12180 使用既有发现失败状态，其他 Win32 错误、超时和非法响应明确报错。超时收尾等待子进程退出；发现 URL 复用既有参数与回环校验。

影响失败不保存坏配置、不静默直连。未部署 WPAD 的网络若选择 WPAD，或 System 仅 Auto Detect，仍按现有失败约定报错。
