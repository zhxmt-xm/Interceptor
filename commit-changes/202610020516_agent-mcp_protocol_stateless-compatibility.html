MCP 三版协议兼容与 Settings 支持说明

提交改动说明 · 2026-10-02 05:16 CST

让旧协议 Client 与新协议 Client 使用同一个 MCP endpoint，并在 Settings 明确显示支持版本。复用官方 SDK，不新增协议选择器、第三方补丁或 Playground Agent。

Agent/MCP

官方 SDK 协议入口

位置：packages/mcp-server/src/server/entry.ts

改前：legacy: 'reject' 主动拒绝2025协议。

改后：legacy: 'stateless' 处理 2025-06-18、2025-11-25，保留 2026-07-28。

原因与影响：不同 Client 可按自身协议访问同一 endpoint；Bearer、Tool 目录、Ask/Auto、参数校验、脱敏和 Main/Core 业务保持共用。2025正常结果由 SDK 通过 SSE 返回，2026继续按需返回 JSON/SSE。

响应流与取消生命周期

位置：McpServer.fetch() 与 McpServer.#trackResponseBody()

改前：HTTP headers 返回后立即移除取消关联；旧协议 SSE 仍在等待审批时，Host 断开可能遗留审批。

改后：合并 HTTP 断连与凭据撤销信号，保留取消关联直到响应正文结束、失败或取消。

原因与影响：Client断开、撤权及 Server 关闭仍作用于真正的在途调用；逐块转交响应，不解析、改写协议消息，也不全量缓冲。

单次 Tool 取消与请求隔离

位置：McpServer.#createSdkServer() 与在途 Tool 取消关联。

改前：旧协议的取消通知通过另一个 HTTP POST 到达，新 SDK Server 找不到原调用；保持连接、只取消一次调用不能移除原审批。

改后：通过官方 setNotificationHandler('notifications/cancelled', ...) 解析通知，按已认证 Client、协议版本及精确 JSON-RPC ID 转发到原业务取消链。

原因与影响：单次取消不关闭整个 Client；不同 Client、协议、数字与字符串 ID 不互相影响。同一范围的重复活跃 ID 明确拒绝并审计，不覆盖原请求，不增加 MCP Session 或自写协议解析器。

UI · Settings / Agent / MCP Server

位置：McpServerSettings 的 Header 下方、Endpoint 上方。

改前：页面没有协议支持范围说明。

改后：常驻显示三个版本和自动适配说明；覆盖全部15种语言，关闭、运行和端口冲突时都保留。

原因与影响：用户可以确认 Client 的协议适用范围，但不用手动选择版本。保持原 Server 开关、Client、Ask/Auto 与凭据操作；窄窗口自然换行，后续内容按自然流下移。

工程与文档

  • SDK/Main 测试使用官方 Client 的正式 legacy 选项和现代 pin，分别检查三版协议、响应类型、认证、审批、凭据和取消。
  • 已有真实 Electron workflow 参数化三版协议；新增版本说明的关闭/运行流程，不增加 Playground 模型配置。
  • 当前开发 Agent 的真实 Host workflow 分为 prepare 与 verify：先通过真实 UI 生成配置并正常退出 App，保留隔离 profile；Host 注册后恢复相同 endpoint 和凭据执行调用。等待期间不占用 App、8888 或系统代理，配置不随等待超时销毁；成功验收后撤销凭据并清理。MCP Tool 由正在开发的 Agent 实际调用，不新建 Agent Runtime。Settings 导航、Copy config 和恢复录制复用同一 UI helper。
  • VS Code Copilot SDK 接入说明使用官方 AHP 配置、Server 启动和已公开的 MCP 工具通道，区分 Host 配置、连接、实际调用与聊天工具搜索；不使用 SDK 私有 RPC，不把配置写入当成调用成功。
  • 设计稿与 Settings 场景截图同步；parity 清理上一场景的 MCP Client、弹窗与 Tool 筛选状态，避免状态残留影响后续场景。
