E2E：恢复产品 Close，移除多余前置

2026-10-03 16:16 CST

普通 E2E 通过产品右上角 Close 退出，不再打开 macOS 菜单 Quit；窗口准备和 Renderer DOM 操作不额外抢占前台。

工程与文档

统一普通退出入口

位置：apps/desktop/tests/e2e-workflow-tests/fixtures/runtime/local-electron-driver.ts

改前

macOS 的普通收尾先激活 App，再打开系统菜单中的 Quit，绕过产品 Close；Windows 使用窗口按钮。

改后

两平台都通过 shell.window.close 进入现有 Main 退出流程，删除 macOS 专用菜单退出实现。

原因与影响：普通流程应覆盖实际产品入口，不靠原生菜单绕开 Renderer。原生快捷键专项仍保留 Command+Q / Alt+F4；macOS 快捷键驱动保留所属 App 的原生焦点检查，删除重复的 CDP 前置。

窗口准备不激活 App

位置：local-electron-driver.ts 的 macOS 窗口尺寸准备

改前

窗口等待过程中显示隐藏 App；System Events 暂未发现窗口时，主动将 App 调到前台。

改后

只核对进程代际、等待真实窗口出现，再按项目配置调整和检查尺寸。

原因与影响：尺寸准备不需要修改前台应用。产品正常启动显示窗口的行为、窗口尺寸及 Windows 逻辑不变。

删除普通流程的冗余前置

位置：workflows/capture/、workflows/composer/、workflows/rules/、workflows/diagnostics/

改前

11 份文件操作 workflow 在原生面板关闭后或普通 DOM 点击前调用 bringToFront()。

改后

删除 53 次冗余前置，继续通过原有 DOM 控件执行操作和读取状态；Open/Save、系统授权及窗口恢复专项仍由所属原生驱动取得必要焦点。

原因与影响：页面内操作不需要 OS 前台焦点。HAR、Archive、正文、Rules、Collection 和 Diagnostics 的输入、文件选择及业务步骤不变。

同步退出与焦点约定

位置：E2E README.md、fixtures/README.md 与 architecture/platform/testing.md

明确普通 Close 和 DOM 操作不主动前置；Renderer 不可操作时不再以菜单退出冒充成功，沿用宿主保护保留尚未恢复代理的 App 和 profile。

本项只调整 E2E 驱动和说明，不修改产品 UI、Main/Core 业务、依赖或第三方补丁，没有产品画面像素变化。
