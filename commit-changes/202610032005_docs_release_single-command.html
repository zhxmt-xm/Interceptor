单命令发版、依赖升级与中断正文修复

类别：工程与文档 · 时间：2026-10-03 20:05（本地时区）

将发版准备统一为一个连续命令，支持源码选择、版本递增与原生目标；升级依赖并修正中断正文边界，自有代码采用Apache-2.0，许可声明随安装包交付。

改动：工程与文档

位置改前改后原因与影响
LICENSE、NOTICE、workspace manifests 未声明自有代码的开源许可证。 采用Apache-2.0；声明版权归属并同步SPDX元数据。各workspace继续保留private: true。 明确源码许可；不改变npm发布限制，也不自动更改GitHub仓库可见性。

scripts/release.mjs及配置、命令、构建辅助脚本 版本、构建目标及GitHub动作主要由维护者分别操作。 npm run release先从最近10个commit或输入hash查询结果选择源码，再选择版本和包类型。CI固定检出该SHA，构建后生成同SHA的tag/draft，验收确认后Publish。 本地未提交修改不参与构建，不要求干净工作区，不改本地版本、index或HEAD，不commit/push/stash。
scripts/release-config.mjs、.github/workflows/release-artifacts.yml tag要求付费签名/公证凭据，并按固定平台与包数量发布。 通过输入传入完整源码SHA、版本和目标，生成原生矩阵；产品源码与workflow工具版本分别固定。只保留4个CI工具后，在同一目录检出所选源码；构建通过后创建tag与draft。 删除本地配置持久化和版本提交路径；不改用main源码，不复制产品仓库，不放宽包类型、数量、大小、SHA-256及许可检查。
.github/workflows/release-artifacts.yml中的官方Actions 固定的旧Action声明Node.js 20，由GitHub强制使用Node.js 24并提示弃用。 更新checkout/setup-node/upload-artifact/download-artifact到声明Node.js 24的官方版本，仍固定完整SHA；工具准备阶段关闭新增的自动缓存。 迁移Action自身运行时，不修改产品Node版本、源码SHA或构建门禁；保留ZIP artifact传递及摘要校验。

改动：Core中断正文收尾

位置改前改后原因与影响
proxy/internal/exchange-tracker.ts 收到abort即结束writer并移除记录，迟到的已观察正文无法追加。 立即发布aborted和原结束时间，每条请求只保留一次1000ms窗口；重复abort或数据不延期。到期在下一次setImmediate封口，再排空写入、提交正文并回收。 尽力保留中断前已经观察、但通知迟到的数据，不继续网络请求；正常完成不增加延迟，也不承诺任意迟到事件都可接收。
capture/entry.ts 网络状态变为终态时自动解除writer关联，将请求结束等同于正文采集结束。 独立登记等待中的正文采集所有权，窗口内仍可读，首个writer可以晚于abort创建；封口且写入结束后明确解绑。 正文只保存一份，不增加“中断后正文”副本；已有Final仍优先于Original，快照完成不等于HTTP完整成功。
Clear、Session删除、Dispose与listener重建 没有需要取消的迟到观测窗口。 删除优先取消等待和排队封口，回收读写资源；listener重建保留已接受字节及原中断时间，正常暂停录制不打断已开启窗口。 防止旧记录复活、writer或计时器残留；BodyWriter接口不变，不添加delayFinalize。
Core回归与现有H2真实workflow 部分断言将网络终态与正文引用提交当作同一时刻。 分别断言即时中断状态、窗口及最终字节/hash；H2集成等待CaptureService真实释放采集关联，再断言最终正文，避免默认轮询时限与1秒窗口竞争。客户端收到前缀后仍立即GOAWAY。 验证迟到数据、重复中断、无正文、Clear与事件循环延迟，不放宽字节预期或增加测试超时。
websocket-bridge.ts与相关回归 同步导入旧版CommonJS HTTPS proxy agent，提前响应回归依赖poll默认时限。 在既有异步选路路径加载ESM代理；提前响应先断言即时aborted，再等待Tracker正式收尾后核对正文引用。 上游选择、认证与字节断言保持，不增加网络重放或放宽测试超时。
Mockttp异常入口、SSE集成与错误处理控制 普通异常会尝试对已销毁的响应写入错误正文；观测流先接收文字，即使客户端没有收到，也可能被Core记录。 原AbortError或response.destroyed && !response.writableFinished走中断收尾，不再写错误正文；同步源码与运行JS，补充真实SSE及正常500、完整响应、原有中断控制。 保留1秒迟到观测窗口和合法正文，不按错误字符串过滤；连接仍可用的错误回包与正常完成保持原行为。
Recording边界的Core存储回归与真实workflow 真实E2E把全局Storage总数不变当作本场景没有补录；恢复Recording时其他应用的新连接也可能进入全局统计。 真实UI按自产路径和原Capture行身份验证暂停期连接不被补录；独立Core集成使用真实CaptureService、BodyStore和随机代理端口，严格比较前后用量及停止后的保留数据。 排除工作环境中的无关流量干扰，同时保留无主正文与完整存储数值约束；删除失去适用前提的全局统计比较，不改录制产品逻辑。
