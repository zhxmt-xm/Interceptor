Apache-2.0 与单命令发版准备

类别：工程与文档 · 时间：2026-10-03 20:05（本地时区）

将发版准备统一为一个连续命令，支持版本递增与原生目标选择；自有代码采用Apache-2.0，并将许可声明随安装包交付。

改动：工程与文档

位置改前改后原因与影响
LICENSE、NOTICE、workspace manifests 未声明自有代码的开源许可证。 采用Apache-2.0；声明版权归属并同步SPDX元数据。各workspace继续保留private: true。 明确源码许可；不改变npm发布限制，也不自动更改GitHub仓库可见性。
forge.config.ts、Vite配置、Core构建与依赖随包脚本、third-party-licenses/ 缺少统一的自有许可随包与内联依赖声明。 复制自有LICENSE/NOTICE；由Vite与Core构建保留依赖许可。npm缺失正文的特定版本使用已核对、记录来源的上游声明。 保留第三方原许可，不将第三方代码改为Apache-2.0；缺少已核对声明时明确报错。
scripts/release.mjs及配置、命令、构建辅助脚本 版本、构建目标及GitHub动作主要由维护者分别操作。 npm run release先从最近10个commit或输入hash查询结果选择源码，再选择版本和包类型。CI固定检出该SHA，构建后生成同SHA的tag/draft，验收确认后Publish。 本地未提交修改不参与构建，不要求干净工作区，不改本地版本、index或HEAD，不commit/push/stash。
scripts/release-config.mjs、.github/workflows/release-artifacts.yml tag要求付费签名/公证凭据，并按固定平台与包数量发布。 通过输入传入完整源码SHA、版本和目标，生成原生矩阵；产品源码与workflow工具版本分别固定。只保留4个CI工具后，在同一目录检出所选源码；构建通过后创建tag与draft。 删除本地配置持久化和版本提交路径；不改用main源码，不复制产品仓库，不放宽包类型、数量、大小、SHA-256及许可检查。
终端发版摘要与确认提示 版本、目标、提交文件和说明混在长行中，确认提示较长。 源码SHA、提交时间/说明、版本和构建目标清楚展示；最近10条可直接选，短hash可查询确认。Yes/No确认默认Yes。 提高可读性；默认Yes仍等待输入，不跳过检查或实机验收确认。
tests/installer/、发布文档与中英文README 说明以双平台签名发行和手动操作为主。 复用实际产物检查，增加App/helper原生架构及随包许可检查；说明单命令流程、正常系统授权、draft验收与失败恢复。 保留Fuses、CSP、ASAR与生产helper鉴权；ZIP-only的内置更新限制明确展示。

边界

  • 不修改代理业务、Renderer页面或产品GitHub登录行为。
  • 不会自动公开仓库、覆盖已发布版本、移动旧tag或绕过系统安全保护。
  • 不修改或提交本地版本和配置；所选commit必须存在于GitHub，未推送时明确拒绝，不自动上传其他工作。
  • 发布确认仍由维护者完成；默认Yes不是自动批准。
