统一开发命令入口

工程与文档 2026-10-03 19:52 CST

新增 npm start，按 Development、Test、Build 组织常用操作。只询问目标和必要范围，自动准备构建文件，以分栏摘要确认后执行。

工程与文档

从分散命令改为分级选择

位置：package.json、scripts/start.mjs

改前

根目录没有统一交互入口。初版菜单又把缓存、构建模式和低频脚本都做成选项，需要调用者理解内部实现。

改后

一级菜单使用 Development、Test、Build。Desktop和Design选择后直接进入启动确认；测试只选择必要范围，Build只保留App和Installer。

npm start
├─ Development → Desktop / Playground / Design
├─ Test → 常用检查 → 必要的 workspace / 范围 / 场景
└─ Build → App / Installer
最后：查看实际命令与影响 → 确认执行

原因与影响：不再要求判断“沿用已有Core”等实现细节。Watch、截图/对比、报告、专项Browser及单独native构建等低频操作退出常用菜单，原始npm命令和CI入口不删除。版本发布不在本次范围，release和release:build独立保留。

保留执行边界与明确确认

位置：scripts/start.mjs 的选择与执行流程

改前

调用者自己确认命令参数、构建前提、平台限制和可能产生的系统操作。

改后

自动完成必要构建，执行前分列展示工作目录、命令顺序与影响；确认默认Yes，仍等待Enter。输入n取消，失败停止后续步骤。

  • workspace和E2E范围来自现有清单；测试自动准备构建并使用既有串行参数，不再询问缓存模式。
  • 不适用的平台操作不可选，真实App和验收操作明确提示系统授权与退出恢复。
  • 资源审计先打包再检查，避免让调用者判断产物是否已经准备好。
  • 命令使用参数数组执行，不把用户输入拼成shell命令；不依赖或修改发版脚本。

原因与影响：让选择过程可见、可取消，同时保持底层开发、测试和构建行为的单一实现。
