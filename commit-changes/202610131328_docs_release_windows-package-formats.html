Windows EXE / MSI / ZIP 发布支持

提交改动说明 · 2026-10-13 13:28 +08:00 · 工程与文档、Core

复用同一应用构建与现有 MSI 安装逻辑，为 Windows 提供三种分发格式，保留 macOS 两种架构的 DMG / ZIP，并让各平台均可发布完整的 alpha 预发布版本。Archive 快照初始化改为单个事务，消除逐条创建 schema 对象时的重复磁盘同步。CI 与完整性检查通过后自动 Publish，不再二次询问。

工程与文档

发布目标与交互选择

scripts/release-config.mjs、scripts/release.mjs

改前

Windows 只能选择 MSI，附件类型统计没有 EXE。

改后

Windows 可选择 EXE、MSI、ZIP，按实际选择计算附件数量；未选择 MSI 时明确说明内置更新限制。

原因与影响：支持面向普通用户的 EXE、标准 MSI 与完整解压包，不把 EXE 或 ZIP 假装成内置更新所需的 MSI。

保留 alpha，而不是改成稳定版

scripts/release-config.mjs、scripts/release.mjs、scripts/windows-bootstrapper.nsi

改前

发布向导禁止 Windows 选择预发布版本；EXE 固定版本字段直接拼接完整版本，不能接受 alpha 标记。

改后

App、tag 和附件名完整保留 alpha/beta/rc。Windows 系统安装器数字版本单独表达，例如 0.1.1-alpha.1 对应内部 0.1.1.0，GitHub 仍标为 Pre-release。

原因与影响：复用 MSI 库已有的版本转换，不通过改成稳定版本绕过限制。同基础版本的预发布在 MSI 层是同版本，系统不按 alpha 序号阻止覆盖；App 版本仍需按完整 SemVer 核对。

EXE 复用现有 MSI

scripts/release-build.mjs、scripts/windows-bootstrapper.nsi

改前

发布脚本仅归集 Forge maker 的直接输出。

改后

选择 EXE 时先构建同一 MSI，再由 NSIS 离线封装；EXE 释放 MSI、显示原生安装 UI 并传递退出码，不写应用卸载记录。

原因与影响：避免第二套安装逻辑或 Burn Bundle 登记；只选 EXE 时，作为 payload 的 MSI 不额外成为 Release 附件。

Windows ZIP 与 CI

apps/desktop/forge.config.ts、scripts/start.mjs、.github/workflows/release-artifacts.yml

  • ZIP maker 从仅 macOS 改为同时支持 Windows，打包完整应用目录。
  • Windows EXE 构建使用固定的 NSIS 3.11；编译器、模板及7-Zip检查只属于构建流程，不进入 App。
  • CI 对比 EXE 内嵌 MSI 与独立 MSI 的 SHA-256，附件统计增加 EXE，诊断产物仍不进入 Release。
  • Forge 配置测试随 Windows ZIP 约定更新；macOS 签名、资源和安装包规则不变。

发布约定

architecture/release-guide.md、architecture/platform/release.md

说明三种 Windows 格式的关系、EXE 的原生 MSI UI、ZIP 解压运行方式及内置更新仍选 MSI 的边界。未改动桌面 Renderer，也未新增第二套安装向导。

发布完成后从 Handover 移除该发布待办，将结果和证据归入发布平台文档；Handover 的验收约束保留未验证范围及 AppContainer 偶发超时风险，不把已发布与实机验收通过混为一谈。

CI 检查通过后直接 Publish

位置：scripts/release.mjs、scripts/start.mjs、Release workflow 的说明文字及开发/发版指南。

改前

CI 生成 draft 后再次询问实机验收与 Publish，输入 No 会留下未发布草稿。

改后

保留源码、版本、目标选择与启动 CI 前的确认；CI 成功后核对 tag、Release 身份与附件，直接 Publish 并读取 GitHub 状态确认，不再二次询问。

原因与影响：按维护者要求连续完成发布；正常向导及已完成 CI 的草稿共用 publishRelease()，导入脚本不会意外启动向导。源码 SHA、附件名称/大小/digest/更新时间、草稿身份及发布后状态检查保留。自动发布不代表实机安装和系统授权已通过，未验证范围继续单独记录。

Core

Archive 快照原子初始化

位置：apps/proxy-core/src/proxy-core/archive/worker/snapshot-store.ts。

改前

完整 schema 的建表、索引和 FTS 语句没有事务包裹，每条 DDL 独立自动提交；初始化中途失败时，连接未关闭，已提交的部分 schema 仍保留。

改后

以 BEGIN IMMEDIATE 和 COMMIT 包裹整个 schema，所有对象只提交一次；初始化失败时关闭连接，回滚尚未提交的 schema 并继续抛出原错误。

原因与影响：避免 Windows 慢磁盘放大重复同步成本，并保证失败不遗留打开的数据库连接。保持 journal_mode = DELETE、synchronous = NORMAL、原有 schema、100 条批次、文件格式及取消时保护原文件的语义；不提高测试超时或跳过检查。

相关位置：archive/tests/integration/snapshot-initialization.test.ts 用真实 SQLite 操作检查全部 schema 对象处于同一事务，并在建表被拒绝时检查连接关闭及部分 schema 回滚；模块 README 与 Transfer 功能文档同步说明该约定。
