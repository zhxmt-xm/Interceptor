Windows EXE / MSI / ZIP 发布支持

提交改动说明 · 2026-10-13 13:28 +08:00 · 工程与文档

复用同一应用构建与现有 MSI 安装逻辑，为 Windows 提供三种分发格式，保留 macOS 两种架构的 DMG / ZIP。

工程与文档

发布目标与交互选择

scripts/release-config.mjs、scripts/release.mjs

改前

Windows 只能选择 MSI，附件类型统计没有 EXE。

改后

Windows 可选择 EXE、MSI、ZIP，按实际选择计算附件数量；未选择 MSI 时明确说明内置更新限制。

原因与影响：支持面向普通用户的 EXE、标准 MSI 与完整解压包，不把 EXE 或 ZIP 假装成内置更新所需的 MSI。

EXE 复用现有 MSI

scripts/release-build.mjs、scripts/windows-bootstrapper.nsi

改前

发布脚本仅归集 Forge maker 的直接输出。

改后

选择 EXE 时先构建同一 MSI，再由 NSIS 离线封装；EXE 释放 MSI、显示原生安装 UI 并传递退出码，不写应用卸载记录。

原因与影响：避免第二套安装逻辑或 Burn Bundle 登记；只选 EXE 时，作为 payload 的 MSI 不额外成为 Release 附件。

Windows ZIP 与 CI

apps/desktop/forge.config.ts、scripts/start.mjs、.github/workflows/release-artifacts.yml

  • ZIP maker 从仅 macOS 改为同时支持 Windows，打包完整应用目录。
  • Windows EXE 构建使用固定的 NSIS 3.11；编译器、模板及7-Zip检查只属于构建流程，不进入 App。
  • CI 对比 EXE 内嵌 MSI 与独立 MSI 的 SHA-256，附件统计增加 EXE，诊断产物仍不进入 Release。
  • Forge 配置测试随 Windows ZIP 约定更新；macOS 签名、资源和安装包规则不变。

发布约定

architecture/release-guide.md、architecture/platform/release.md

说明三种 Windows 格式的关系、EXE 的原生 MSI UI、ZIP 解压运行方式及内置更新仍选 MSI 的边界。未改动桌面 Renderer，也未新增第二套安装向导。
