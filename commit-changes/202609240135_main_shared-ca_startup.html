提交：平台能力归属、共享 CA 与启动操作

时间：2026-09-24 01:35（UTC+08:00，本地时间）

Main 通过唯一平台对象调用各模块；CA 和 macOS 代理恢复记录移出业务 profile。首窗先显示，再按需准备组件与证书；冲突立即返回，不排队重放。本报告统一说明原第 1–5 项及直接相关改动，不追加到历史 helper 报告。

Main

位置改前改后原因与影响
platform-capabilities/ 与 main.tsMain 直接持有子服务，证书材料与系统信任分离；代理步骤、upstream 和图标缓存散落在 Main。Main 只持有 readonly PlatformCapabilitiesService。证书、系统代理、AppContainer、helper 和 Client App 分属模块；材料与 Trust Store 合入 CertificateService，各模块管理自己的状态与 Core 同步。IPC、Agent、MCP 共用同一业务入口；私钥不交 root helper，不引入独立 package。
getCertificateDirectory() 与 main.ts两端均使用 userData/certificates，fresh profile 没有原 CA。Windows 使用 LOCALAPPDATA/Interceptor/certificates；macOS 使用用户 Library 下的 Interceptor Platform/certificates。同一 OS 用户跨 profile 复用，不迁移旧材料，不共享规则、会话、凭据或 Tool 授权。
PlatformCapabilitiesService.prepare() 与 Main 启动平台准备发生在首窗前，启动只查询已有 CA。先显示启动页，再准备 helper、恢复系统代理、检查共享材料和真实信任；全缺才生成，未信任才安装并回读，ready 前拒绝业务 IPC。Windows 保留 certutil/UAC，macOS 保留前台 helper 系统确认。失败沿 Main 收尾，不把命令成功当作已信任，不自动开启 MITM。
CertificateService.ensure() 与材料写入文件缺失或元数据不可读时可能直接覆盖重建。仅全部缺失时生成；残缺、损坏、过期、指纹/密钥不匹配均保留并报错；新目录 0700、文件 0600。避免替换长期共享私钥；使用 Node X.509 和密钥校验，私钥仍经 safeStorage 加密。
平台模块操作与 Main Quit代理操作进入 Promise FIFO，调用方 signal 参与平台步骤。各模块持有自己的在途状态，冲突立即返回 operation_in_progress；平台调用开始后完整收尾，不接受外部 signal。忙时拒绝本次 Quit，不保存延后退出。用户拒绝的操作不会后来突然执行；Core 故障恢复与必要回滚仍由所属模块完成。
helper-deployment.ts、typed client 与 macOS 原生部署已结束的只读部署检查或生效代理快照解析失败可能被记为未知写入；launchd 使用 ProcessType=Background。已结束的只读检查显式返回 completed；生效代理快照解析错误保留只读 operation。同步服务 Main 的 helper 使用 Interactive。只读失败不再错误保留准备或代理占用；避免后台 CPU/I/O 限制拖慢响应。完整签名、资源、运行时鉴权和 30 秒期限不变；真正未知写入仍保守保持占用。
macOS journal、恢复 driver 与宿主 guardjournal 跟随 userData，崩溃恢复依赖原 profile。恢复文件放在用户 Library 的 Interceptor Platform/system-proxy，另一 fresh profile 读取同一份 original/owned/effectiveProxies。OS 代理恢复记录不随业务 profile 删除而丢失；保留外部修改保护，不增加旧路径迁移，Windows 路径和格式不变。

Core 与 Agent/MCP

位置改前改后原因与影响
ProxyService HTTP 转发规则源站证书例外变化时追加新规则，旧规则仍可能匹配首笔请求。使用 Mockttp 公开 setRequestRules() 替换整组 HTTP 转发规则。启动即加载共享 CA 时，首笔请求也遵守最新例外；不重启 listener，不改变 WebSocket 规则或 Capture 会话。
Client App 名称与 native build 入口Windows helper 的 imagePath 按宿主平台解析；构建脚本引用旧目录。按 path.win32 提取名称，构建和依赖路径跟随平台模块目录。macOS 上检查 Windows helper 数据时得到相同名称，原生产 native 产物路径不变。
interceptor-tools/settings/ 与 Main 导入入口平台冲突被包装成普通失败；普通 UI 导入创建占位 controller。Tool 保留结构化平台冲突和当前 operation；Agent/MCP 在进入平台前检查取消，普通导入只在确有调用方 signal 时传入。UI 与 Tool 得到一致的冲突原因，不在不同入口复制业务或取消逻辑。

UI：启动阶段与操作冲突

  • 启动窗口 / BootScreen：增加平台、证书阶段文案；准备期间只挂载启动页与既有 WindowControls，ready 后挂载业务 App。沿用原控件和布局，不修改设计 token。
  • 全局消息 / 窗口关闭操作：冲突使用既有 Ant Design warning message，显示本地化的当前操作；消息在启动页和业务 App 都能接收。

工程与文档

位置改前改后原因与影响
CA fixture、普通 HTTPS/TLS workflow 与 packaged smoke每个 workflow 生成、安装、卸载并删除 profile 内 CA。普通流程只读检查并复用共享 CA，清理 profile 内配置；首次初始化和破坏性专项独立声明范围。保留共享材料和系统信任；专项只能清理空目录前提下本轮产品生成的 CA，不增加产品测试参数，不预造 CA。
证书生命周期/Tools 与共享启动 workflow跨代检查按 profile 内未受信任 CA，部分清理依赖手工生成后的指纹。共享启动检查跨 fresh profile 的同指纹与文件不变；已有未信任 CA 重启仅补授信；清理使用启动前系统 Root 基线。保留真实 UI、Agent/MCP 审批及系统确认，既有共享 CA 不作为删除目标。Windows 实机验收单独跟踪。
macOS driver 与 packaged smoke后台 App 的菜单可能尚不可用；Core running 被当成自动接管结束。原生 Quit 核对 Main 代际、前置所属 App 并等待菜单；smoke 等公开 Recording 状态就绪，再经 Settings UI Restore。不点击其他 App，不用 API 绕开产品流程，不为旧 fixture 恢复操作队列。
parity fixture 与 harnessHTTP 头部断点被声明已有 snapshot 正文；缺失元素未计入进程失败状态。HTTP snapshot 使用 bodyAvailable: false，WebSocket 保持完整 payload 语义；missing/flagged 均返回非零，浏览器直连仅作用于 parity。复现真实契约，不更改产品 UI、正式设计基准或阈值；不改变系统代理。

不包含暂停的 HTTPS 弹窗定位、正文候选、Bilibili、独立 platform-capabilities package 或待确认的 GitHub 登录设计。验证结果、剩余任务与恢复命令只保留在 Handover。
