H2 正常 GOAWAY：完整排空响应

2026-10-02 09:50 CST

源站已正常结束响应时，Interceptor 仍须把已收到的正文与 trailer 完整交给客户端。此次改动由 Core 管理 TLS/H2 收尾，不新增或修改任何第三方 patch。

Core

暂停响应与正常关闭

位置：apps/proxy-core/src/proxy-core/http2-client/entry.ts

改前

TLS 可读端结束后自动关闭写端，H2 session 提前销毁。已经到达 Core、但尚未被断点后的消费者读取的正文被丢弃；客户端缺少尾段、trailer 和正常结束。

改后

通过 Node 公开 channel 和 session.socket.allowHalfOpen 保留现有缓冲。TLS EOF 后不再接受新 stream；旧 stream 按自身背压排空，随后正常关闭。

原因与影响：源站 session 结束不等于下游已消费完整响应。该策略不注册正文消费监听、不复制完整正文、不重放 POST；新请求使用新的上游 session。

真正提前 EOF 的显式失败

位置：http2-client/entry.ts、http2-client/internal/errors.ts

改前

缺少最终响应头或 END_STREAM 的连接关闭可能被当成正常结束；只开启半关闭保护又可能让未完成的 stream 一直等待。

改后

在 EOF 或消费者恢复后，先让待派发的 DATA/END_STREAM 执行。没有最终响应头，或已排空仍未正常结束时，使用 ERR_H2_UPSTREAM_INCOMPLETE 进入既有错误路径。

原因与影响：既不能误伤正常 DATA.END_STREAM，也不能伪造成功。Proxy/Capture 保留中断语义，Composer 返回失败；原有取消、错误 GOAWAY 和显式 timeout 不被改写。

Core 代际所有权

位置：core-application.ts、http2-client/interfaces/index.ts

改前：Proxy 与 Composer 的出站 H2 连接没有统一的 EOF 排空所有者。

改后：CoreApplication 唯一拥有 Http2ClientService，启动时订阅，退出时注销并清理自身监听和排空检查，等待已观察 session 关闭后确认 stopped。

影响：策略只管理本 Core 进程的出站 TLS/H2；Main、Renderer、入站 server session、明文 H2 与只握手 TLS 探测保持原路径。不引入原始 H2 帧采集或猜测请求关联。
