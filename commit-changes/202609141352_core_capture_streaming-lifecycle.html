提交：Capture 流式正文与生命周期

时间：2026-09-14 13:52（本地时间）

gRPC 不再等待整个 HTTP body 结束才显示消息。正文仍只保存一份，按需读取已有内存或 spill 中的有限范围。

摘要

  • Request / Response 在途消息按完整 envelope 逐条出现；半个 header 或 payload 等待补齐，完成态仍保留真实损坏与截断信息。
  • Capture 统一管理 writer、读取与 Clear / Dispose 的顺序；Rule Final 优先，显式空 Final 不回读原文。
  • HTTP 与 gRPC workflow 增加受控流量、进行中状态、取消、Pause / Resume 和 Clear 的操作与证据采集。

Core

位置改前改后、原因与影响
capture/internal/body-writer.ts
capture/internal/body-store.ts		writer 只提供 write / finalize / abort；hash 结束后才确定，不能读取在途正文。提交失败后仍可能报告正文可读、尚未结束。增加 snapshot / readRange；内存分片按所需范围拷贝，spill 使用同一可读写句柄。读取进入原串行队列，finalize / abort 不抢先关句柄；提交失败仍抛出原错误，同时结束快照并标为不可读，保留observed计数及文件清理责任。提交后通过 BodyStore 读 hash，不复制完整 stream。
capture/entry.ts
capture/interfaces/index.ts		Capture 不保存 writer 与 Exchange / side 的对应关系；只能按完成的 hash 读取。在途快照等待期间即使已绑定 Final，也可能返回旧原文状态。按 Exchange / side 登记非终态 writer，返回独立的可用、完成和可读大小。等待 writer 快照后再次检查 Final 和 Exchange，显式空 Final 也优先；Clear / Dispose 等待已接受的读取与 writer 清理。Final 替换不提前丢失原 writer 的清理所有权。
proxy/internal/exchange-tracker.ts创建writer时没有Exchange/side身份；任一提交失败会跳过另一侧和终态，详情可能仍停在response-streaming。settle只查看活动Map，记录提前移出后不再等待剩余写入。创建writer时传入Exchange/side。请求提交、响应提交和终态分别排入原串行队列，逐次记录失败并保留成功正文。独立跟踪待完成写入，终态/reset不丢失排空责任；只等待调用时已接受的一批，完成后移除，不阻塞后续流量。
proxy/entry.ts · prepareCaptureReset()Clear只等待WebSocket等Capture操作，终态HTTP正文可能仍在提交，随后清理会与写入竞争。推进generation后先等待Exchange存储队列，再等待原Capture操作，最后交由调用方清理正文；网络响应不等待捕获落盘，Recording暂停语义不变。
grpc/entry.ts
grpc/interfaces/index.ts		没有 bodyHash 时返回空消息；查询依赖完整 body。超过当前正文长度的游标被当成已读尽，无法暴露非法输入。按当前快照只跳读 5-byte header，列出已收齐的消息；未完成 envelope 保留续读游标，不提前标损坏。末尾游标可继续等待在途消息，超过末尾则返回已有的不可重试输入错误。独立返回 bodyAvailable / bodyComplete，在途不伪造 hash。
core-application.ts
packages/core-protocol/src/messages.ts		正文读取命令必须提供内容 hash。新增 grpc.read-range / grpc.range，按 Exchange、side、offset、length 读取现有 Capture 正文；原 body.read-range 与导出命令保留。
transfer/entry.ts
CoreApplication.shutdown()		cancelAll只发出取消信号，Core随后释放Capture；公开cancelled状态出现时文件操作可能仍在清理。跟踪实际任务Promise，取消所有任务后等待操作和清理结束，包含此前已取消的任务。Core同时停止Proxy，等待两者后才释放Capture并确认stopped；单任务Cancel状态、完成通知及Clear策略不变。

对应产品测试补充在途内存 / spill 读取、半帧、分页游标、Final 优先级、读取与清理竞态、提交失败后的快照、双侧终态收尾，以及文件任务取消后的清理顺序；原 Proxy 测试写入器联动父类构造参数。

工程与文档

  • proxy/tests/integration/h2.test.ts：原helper只返回完整响应，缺同连接多stream的进行中观察；提取可复用H2连接，新增双6 MiB Range的正常完成、Clear和单流取消。使用真实Capture记录与有限正文读取，保留既有ALPN、压缩、gRPC及H2转H1场景，不改产品转发。
  • http-scenarios.workflow.ts：增加 SSE 正常 / 取消 / reset、6 MiB chunked / Content-Length / 100 Continue 上传、4 MiB 上传取消，以及长下载正常 / Pause / Clear；在流未结束时核对列表增长、origin 接收和身份，不以最终结果代替进行中状态。
  • grpc-scenarios.workflow.ts：增加单向 / 双向分段消息、半帧、真实 Copy、Pause / Resume 和 Clear；原压缩、损坏、trailers 与 UTF-8 场景仍保留。背景 TLS 提示通过真实 Not now 处理；总预算由180秒改300秒以容纳完整场景和CA清理，单步断言不变，不改变产品策略。
  • tools-transfer-jobs.workflow.ts 与 fixtures/runtime/local-electron-driver.ts：原流程先取消并等待任务结束才关闭；现在保留该流程，再增加Archive运行中直接退出及重启检查。进度遮罩会挡住自绘Close，因此先核验测试Main的PID、启动代际和前台窗口，再发送真实Windows Alt+F4；不改遮罩、不先取消任务、不注入业务API或原生Dialog结果。
  • apps/playground/server/tls/traffic.ts：既有 TLS origin 支持受控请求 / 响应 AsyncIterable；使用 Node HTTP/2 和 pipeline，复用原 gRPC envelope 编码，不新增另一套协议服务。
  • fake-interceptor.mjs：完成态 gRPC fixture 补独立状态与新 range 入口；设计稿与 PNG 不变。Renderer 逻辑测试补在途续读、迟到分页隔离与非零 offset 的分块读取。
  • Capture / Grpc module README、Capture 功能约定、真实 workflow 规格及进程 / 存储说明同步新读取和生命周期契约。
