UI · Inspector URL 就绪后才显示 Copy

位置改前改后原因与影响
RequestInspector.tsx 的标题 Copy 与 General / Request URL；所属 URL 就绪测试及 Capture fullscreen workflow 详情尚未返回就显示 Copy，并可能复制缺少协议和端口的 host/path；切换请求时也可能使用上一条详情。 只使用与当前选中请求 ID 一致的完整 URL；未就绪时不显示标题 Copy，General 也不提供短标题复制。就绪后的外观和复制内容格式不变。 阻止尚未具备完整数据的操作，不增加额外详情请求、缓存或 API。保留同一请求刷新时已有 URL；不改 Header CSS、字体、间距及 hover 目标。

以下为同一主题、窗口尺寸和 JSON 请求状态下的真实产品截图，均截于 URL 已就绪时。红框标记行为发生变化的按钮位置，不表示稳态布局改变；未截获改前瞬时加载态，不伪造该画面。实际改变是未就绪或详情不属于当前请求时，标题 Copy 从存在变为不渲染；已就绪时仍使用原 30×30px 命中区。

Main · Windows 共享 CA

位置改前改后原因与影响
packages/platform-capabilities/src/certificates/entry.ts Windows 私钥虽放在共享目录，但使用依赖原 Electron profile 的 safeStorage 密文；其他 profile 不能保证解开。 Windows 直接保存当前用户共享目录中的 root-key.pem，与公开 CA、元数据放在一起。macOS 保持 root-key.enc 和原加密实现。 同一用户的不同 profile 复用同一 CA，不新增 PowerShell 加解密、密钥服务或依赖。私钥不额外加密，依靠用户目录权限保管，不能随公开证书分发；Agent/MCP 凭据不变，不增加旧密文迁移。

Core · 两处启动边界

位置改前改后原因与影响
apps/proxy-core/src/proxy-core/workspace/entry.ts 数据库父目录可能尚未由其他模块创建，Workspace 就尝试打开 SQLite。 打开数据库前自行创建父目录。 消除 fresh profile 的目录准备竞争；不共享不同 profile 的数据库，不改变表结构、默认值或业务启动顺序。
apps/proxy-core/src/proxy-core/proxy/entry.ts 未加载真实 CA 时仍可进入解密状态，可能出示仅供分流器使用的临时身份。 没有 CA 就显式拒绝开启解密，保持原状态。 不能以临时证书冒充用户安装的 CA；不修改证书安装、系统信任或正常配置 CA 后的行为。
