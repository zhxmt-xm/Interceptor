提交：Settings Storage 用量与清理简化

时间：2026-09-16 00:46（本地时间）

把重复且容易误解的存储统计合并为一项正文用量，刷新移至右上角，并明确两处 Clear 是同一个操作。

UI

位置改前改后原因与影响
Settings / Storage · 标题与用量标题容量badge重复；Usage同时列Total on disk、恒为0的Capture database及Response bodies。移除重复badge，用量只保留Captured body data，说明包含内存和临时文件中的正文；保留Session、Exchange和正文数量。不再把正文总量误称为磁盘占用；Core返回字段保持，Agent/MCP查询不变。
Settings / Storage · RefreshMaintenance内有独立刷新行，使用带文字按钮。标题右上放30px刷新图标按钮及Tooltip；加载时旋转并阻止重复操作。刷新更易找到，不占一整行；仍为用户主动查询，不增加后台轮询。
Settings / Storage · Clear泛称清空全部数据，没有说明与Capture列表清空的关系。提示两处Clear相同，记录和正文一起删除，已保存文件及录制状态不变；保留取消与二次确认。不引入正文单独删除或任务历史清理，继续使用同一Preload/Main/Core命令。
SettingsRow 与15语言文案行仅支持一条提示；旧Storage标签保留数据库、磁盘总量等含义。行可选第二条提示和局部布局class，Storage清理行在窄窗口可换行；所有语言更新统计与清理说明。普通Settings行的默认结构和样式不变，不让长翻译遮住确认按钮。
design-vite / Settings / Storage正式设计缺少Storage内容，审阅对照可能为空；曾提供独立预算配置提案。默认使用已确认的简化页面，覆盖正常、确认、空数据和不可用；不提供预算、配额或期限输入。产品与正式设计一致；未确认的其他页面草案不属于本次改动。

工程与文档

Storage Renderer测试与真实workflow覆盖刷新、取消和两个Clear入口；补齐公开Session/清理控件标识。Parity配置只增加Storage场景及独立fixture输入，截图脚本增加四种Storage状态；规格、设计规范与状态导航随同更新，不修改产品数据接口或第三方依赖。
